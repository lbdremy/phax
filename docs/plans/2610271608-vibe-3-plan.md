# Mistral Vibe 3

The only plan of the vibe-3 spec. Mistral Vibe 3.0.3 changed every surface phax reads. Its stream lines are typed entries whose `content` is an array of blocks. Its sessions moved to `logs/session/unified/<id>/`, with no `messages.jsonl` and no `stats` in `meta.json`. The session id, usage and cost now come in an `export.json` that `--output-dir` writes on every exit. phax cannot run a single Vibe 3 session today. Vibe 3 can also confine a session, as long as phax stops running it under `auto-approve`, which turns every control off.

phase-01 changes the persisted Vibe usage to tokens and cost read from the export, at $schema 0.30.0. phase-02 makes the run path read Vibe 3: the stream, the export, the transcript from the kept streams, the version floor, and no read of Vibe's home. phase-03 confines secure mode and records Vibe as `strong`/`prefix`. phase-04 makes read-only sessions, stop turns and sealed completions narrow Vibe's tools, and removes the writing-closing-turn path that only Vibe used. phase-05 runs the real-CLI e2e suite on Vibe in secure mode and updates the docs. Every commit is green under the `standard` gate profile.

Facts every phase can rely on, from live probes against Vibe 3.0.3 on 2026-10-27; the probe streams and exports are reproduced as fixtures in phase-01 and phase-02:

- Stream entry (one per line): `{"id":…,"sessionId":"b8e0e3a1-9ad8-2100-46e7-4a199256f640","turnId":…,"createdAt":1793116136395,"type":"message","role":"assistant","content":[{"type":"text","text":"PONG"}],"source":"harness","outcome":{"type":"committed"},…}`. Tool calls are `type: "effect"` entries (`detail.toolName` such as `file_system.bash`, `state.status`, `state.decision`), and approvals are `type: "callback"` entries.
- `export.json`: `{"outcome":"finished","stop_reason":null,"error":null,"session_id":"b8e0…","usage":{"input_tokens":10987,"output_tokens":3,"cached_input_tokens":3200,"total_tokens":10990},"cost_usd":0.016503,"steps":1,"schema_version":1,"vibe_version":"3.0.3","journal_dir":"session","started_at":…,"ended_at":…,"limits":{…},"exit_code":0,"config":{…}}`. Usage and cost count the run only, never the earlier turns of a resumed session. The output directory also receives a copy of the session journal under `session/`.
- `vibe --version` prints `vibe 3.0.3`.
- Secure controls, all per invocation through the environment: `VIBE_OUTSIDE_WORKDIR=deny`, `VIBE_TOOLS='{"bash":{"permission":"ask","allowlist":[…]}}'` (JSON), with `--agent accept-edits`. Headless, a call no rule allows is refused (`tool_denied`, or "denied by approval policy"), the model reads a tool error, and the run goes on.
  - `git status && touch x`, `git status; touch x`, `git status | tee x`, `git status $(touch x)`, `pwd` and a background `process.start` were all refused under allowlist `["git status"]`.
  - `write_file` and `edit` inside the workdir ran.
  - `run_typescript` has no IO of its own.
- `--enabled-tools read_file --enabled-tools grep` refuses `write_file` and `bash`. `--disabled-tools '*'` refuses every tool call, and the model still answers.
- Vibe merges config layers deeply: environment over user TOML over defaults, a list replacing a list, and unset keys kept from below. A user's `bypass_tool_permissions = true` or a file tool's `allowlist` would therefore survive unless phax sets those keys itself.

## Technical arbitrations

- Where a turn's Vibe export lives. Each headless Vibe turn gets `--output-dir` set to the turn's transcript path with `.jsonl` replaced by `.vibe-export` (`output.jsonl` → `output.vibe-export/`, `fix-01.jsonl` → `fix-01.vibe-export/`), so the export sits beside the stream it belongs to. One pure function in `src/domain/records/usage.ts`, `vibeExportDirOf(transcriptPath)`, names that directory for both the writer (the adapter) and the readers (record usage, cost ledger). A Vibe turn without `outputJsonlPath` is refused before spawning. Loss accepted: every Vibe caller must give a transcript path, as every caller in `src/app` already does.
- Usage counts every turn. A Vibe session's usage is the sum of its turns' exports, one per transcript the caller lists, never deduplicated by session id: each export counts its run only. A phase record keeps counting the turns it counts today for Claude Code and Codex (`output.jsonl`). Loss accepted: none. The old dedupe existed only because `meta.json` held whole-session totals.
- The transcript of a Vibe session. A stop's transcript capture needs the folder where phax kept the streams, so `TranscriptRequest` gains a required `phaseFolder`. The Vibe capture lists the `*.jsonl` files directly in it and keeps those whose first decodable entry carries the session id. It orders them by that entry's `createdAt`, concatenates their bytes, and returns `missing`/`not-found` when none matches. Claude Code and Codex ignore the new field. Loss accepted: a session the person ran in Vibe's TUI has no transcript (spec §5.4b).
- The version floor. The adapter runs `vibe --version` once per process (memoized per executable) before its first Vibe session, and refuses below 3.0.3 with `mistral-vibe <found> is installed; phax needs Mistral Vibe 3.0.3 or later (uv tool upgrade mistral-vibe)`. An unparseable answer refuses too, naming what it printed. The refusal is an `AgentInvocationError`, which `provider-failures` will later classify. Loss accepted: one short process per phax process that uses Vibe.
- The secure environment. Secure mode sets `VIBE_OUTSIDE_WORKDIR=deny`, `VIBE_BYPASS_TOOL_PERMISSIONS=false` and `VIBE_TOOLS`. `VIBE_TOOLS` is one JSON object holding `bash` with `permission: "ask"` and `allowlist` equal to the session's agent commands, and `read_file`, `write_file`, `edit` and `grep` each with `allowlist: []`, which replaces any user allowlist. The argv carries `--agent accept-edits`, `--workdir`, and `--add-dir` for each writable root beyond the worktree, as today. phax never writes the user's config. Loss accepted: a user's own allowlist entries do not reach secure phax sessions.
- Narrowing. A read-only session runs `--agent accept-edits --enabled-tools read_file --enabled-tools grep`. When it has agent commands, it adds `--enabled-tools bash` and the secure `VIBE_TOOLS` with those commands, plus `VIBE_OUTSIDE_WORKDIR=deny` and `VIBE_BYPASS_TOOL_PERMISSIONS=false`. A sealed completion runs `--agent accept-edits --disabled-tools '*'` with the same two variables, `--workdir` set to the completion's cwd, and no `--add-dir`. Loss accepted: the model still sees tool names in its prompt; its calls are refused, as the probes show.
- Removing the writing closing turn. Once every provider's stop turns are read-only, `turnsCanWrite` and the restore of an interrupted writing closing turn's edits (`LeftoverSettlement.restoredClosingTurn`, its kept versions, its stop-output line) have no provider left. phase-04 removes them rather than leaving a branch no provider takes. Loss accepted: an interactive-session document an older phax left with a Vibe writing closing turn in progress is settled as a read-only turn: its edits stay in the worktree, and the next close's worktree comparison reports them.
- Persisted usage at 0.30.0. `VibeTokenUsage` becomes `{ provider, inputTokens, cachedInputTokens, outputTokens, costUsd }`, all required (spec q-tool-calls: drop). Every format embedding it moves to a `next` snapshot at 0.30.0, and its current shape is frozen under `src/schemas/history/<format>/<stamp>.ts` with stamp routing, as commit 351d3267 did for decision-record-manifest 0.25.0. `provider-failures` also moves decision-record-manifest to 0.30.0: whichever plan runs second finds `next.schema.json` and the frozen 0.28.0 module already there, and only edits the current shape. Loss accepted: an older `@lbdremy/phax-schemas` cannot read 0.30.0 records, as with every shape change.
- Order with `provider-failures`. That spec's Vibe session-outcome reader must read the V3 stream and export this plan establishes. Run this plan first; its Vibe reader then reads `export.json`'s `outcome`/`exit_code` instead of the transcript.

## phase-01 — Vibe usage from the export, at 0.30.0 {#phase-01-vibe-usage}

**Recommended model:** claude-sonnet-5-5
**Recommended effort:** high
**Assignment reason:** four persisted formats change shape at once, each with a frozen module, stamp routing and snapshots; a missed one breaks reading existing records.

Record a Vibe session's usage as tokens and cost read from its turns' Vibe exports, in the 0.30.0 record shape, so records and the cost ledger count Vibe 3 sessions again.

### Detailed instructions

- Add `src/schemas/vibeExport.ts`, the decoder of Vibe's `export.json` at `schema_version: 1`. It decodes only what phax reads: `schema_version` (literal 1), `vibe_version`, `session_id` (string or null), `outcome` (string), `exit_code` (number), `usage` (null, or `input_tokens`, `output_tokens`, `cached_input_tokens`, `total_tokens`, all numbers), and `cost_usd` (number or null). Ignore unknown keys: the export carries `config`, `limits`, `subagents` and more. Export a `readVibeExport(text)` that returns the decoded value or `undefined` for non-JSON or a decode failure.
- In `src/domain/records/usage.ts`, replace `extractVibeUsage(metaJsonText)` with `extractVibeExportUsage(exportText): VibeTokenUsage | undefined`. It returns undefined when `usage` or `cost_usd` is null. It maps `input_tokens` → `inputTokens`, `cached_input_tokens` → `cachedInputTokens`, `output_tokens` → `outputTokens` and `cost_usd` → `costUsd`. Add `vibeExportDirOf(transcriptPath)`: the path with its trailing `.jsonl` replaced by `.vibe-export`. Also add `vibeExportFileOf(transcriptPath)`: `<that dir>/export.json`.
- In `src/schemas/runRecord.ts`, `VibeTokenUsageSchema` becomes `{ provider: "mistral-vibe", inputTokens, cachedInputTokens, outputTokens, costUsd }`, every field a required number. Remove the four tool-call fields. Update its doc comment: the values come from the turns' Vibe exports.
- In `src/app/recordPlumbing.ts`, the Vibe branch of `computeSessionUsage` reads each listed turn's export at `vibeExportFileOf(join(folder, turn.transcript))` through the FileSystem port. It sums every turn with no dedupe by session id. Any missing or unreadable export makes the whole usage unavailable, as for the other providers. `addUsage` sums the new fields. Drop the `ProviderStoreRoots` read and `readVibeSessionMetaText` from this file; the store finder module itself is removed in phase-02. Update the doc comments of `computeRecordUsage` and `computeSessionUsage`, and the comments in `src/app/writeRecord.ts` and `src/app/writeAuthoringRecord.ts` that describe `meta.json`.
- Mirror the shape in `packages/schemas/src/formats/recordManifests.ts` and wherever the package's interactive-session format embeds token usage (`packages/schemas/src/formats/interactive.ts`).
- Move every format whose decoder embeds `TokenUsageSchema` to 0.30.0. These are `phase-record-manifest` (0.26.0), `authoring-record-manifest` (0.23.0), `decision-record-manifest` (0.28.0) and `interactive-session` (0.26.0). Check `src/schemas/costLedger.ts` too, and include it if it embeds the Vibe shape.
  - For each, freeze today's shape as `src/schemas/history/<format id>/<current stamp>.ts`, unless such a module already exists.
  - Route documents stamped at or after that stamp but below the current one to the frozen decoder, lifting them unchanged into the current shape. A frozen Vibe usage with tool-call counts lifts to `{ available: false }` usage, since its fields cannot be mapped.
  - Follow the pattern commit 351d3267 used for decision-record-manifest 0.25.0, and read `src/schemas/persisted.ts` for how stamps are routed.
  - Run `pnpm exec tsx scripts/schemas-check.ts --write` to record the `next` snapshots, `history.lock.json`, the generated index and `src/schemas/release.ts`.
- Remove `extractVibeUsage` and its tests. Add `tests/unit/vibeExport.test.ts` with the two probe exports as fixtures (10987/3200/3 at 0.016503, and 34588/9600/288 at 0.054042), an export with `usage: null`, a non-JSON text, and an export with unknown keys.

## phase-03 — Confine secure Vibe sessions {#phase-03-secure-vibe}

**Recommended model:** claude-sonnet-5-5
**Recommended effort:** high
**Assignment reason:** this phase moves a provider's recorded security posture; a missed key in the environment silently widens what a secure session may do.

Run secure Vibe sessions under Vibe 3's own controls, so that edits stay inside the writable roots, the shell runs only the agent commands, and no user config can widen it. Record Vibe as `strong`/`prefix`, so that strict secure routing accepts it.

### Detailed instructions

- `src/infra/providers/mistralVibe.ts`:
  - `buildVibeSecurityFlags` keeps unsafe mode as `--agent auto-approve --trust --workdir <cwd>`.
  - Secure mode (and isolated, for totality) gives `--agent accept-edits --workdir <cwd>` plus `--add-dir` for each writable root beyond cwd. It still throws `SecurityEnforcementError` when `allowWrite` is empty.
  - Return the environment beside the argv, for example as `{ args, env }`. The secure environment is `VIBE_OUTSIDE_WORKDIR=deny`, `VIBE_BYPASS_TOOL_PERMISSIONS=false`, and `VIBE_TOOLS` as one JSON object: `bash` with `permission: "ask"` and `allowlist` equal to `options.agentCommands ?? []`, and `read_file`, `write_file`, `edit` and `grep` each with `allowlist: []`.
  - `entry.defaultAgent` keeps overriding the agent name in unsafe mode only. Secure mode always uses `accept-edits`, because a custom agent could carry the yolo safety level.
  - `spawnVibe` merges the environment over `process.env`, so a `VIBE_*` variable the user exported cannot loosen it.
