# Archive unfinished runs

Implements spec 32: `phax archive` accepts any run that is not executing. A
finished run (`review_open`, `completed`) archives exactly as today. An
unfinished run (`created`, `failed`, `interrupted`, `rate_limited`, `stopped`)
is refused by default with a message naming its state and `--force`, and
archives with `--force` through the existing move-and-prune mechanics. A
`running` run, a locked run, and an already-archived run stay refused whatever
the flags. The consent lives in the run state machine's archive rule (spec §10,
arbitration below), never in a bypass around it. No new state, field, or
command; the recorded `stoppedReason` and `lastError` already survive archival.

## Technical arbitrations

- **Consent is a field on the event, decided in the reducer.**
  `RunArchiveRequested` gains a required `force: boolean`; the reducer archives
  an unfinished run only when it is `true` and rejects otherwise with a reason
  that names `--force`. Loss accepted: the pure state machine carries an
  operator flag. The alternative (app layer decides, reducer accepts every
  non-running state) would let any future caller archive an unfinished run with
  no consent at all. Decided with the operator on 2026-09-03.
- **The audit matrix keeps documenting the unconsented path.** The
  `sampleEvents.RunArchiveRequested` used by the matrix walker carries
  `force: false`, so every unfinished-state cell stays `Rejected` and the matrix
  needs no edit; the consented path is covered by explicit per-state reducer
  tests. Loss accepted: the matrix does not show the widened rule. Making the
  sample carry `force: true` would flip five cells to `Handled` and hide the
  default refusal, which is the behavior an operator meets first.
- **One new refusal error, built from the reducer's reason.** A
  `ArchiveRefusedError` (fields: `shortName`, `state`, `message`) replaces the
  generic `InvalidTransitionError` for every `Rejected` archive dispatch; its
  message is the reducer's reason plus, for an unfinished run without consent,
  the `--force` remedy. Loss accepted: one more error class. Widening
  `InvalidTransitionError`'s message with a remedy would make its single
  meaning a switch.
- **The dirty-worktree guard applies to finished runs only.** The final-worktree
  cleanliness check runs when `--force` is absent *and* the run is finished.
  For an unfinished run without `--force` the reducer's refusal is the one the
  operator sees (spec §5.2 names the state, not the worktree); with `--force`
  no cleanliness check runs at all (§5.4). Loss accepted: the use case reads
  `runState` to pick which guard applies. The alternative (keep the guard
  unconditional) would show a dirty-worktree message on an unfinished run and
  hide the state refusal the spec requires.
- **`archiveRun` in `state.ts` is left as is.** It is deprecated, uncalled at
  runtime, and has no `force` parameter; widening it would invent a second
  rule. Loss accepted: its unit test keeps asserting the old, narrower set.

## phase-01 — Consent-aware archive rule and refusal {#phase-01-archive-rule}

**Recommended model:** claude-sonnet-4-6
**Recommended effort:** high

The archive use case archives any non-executing run: an unfinished run is
refused without `--force` by a message naming its state and the flag, archived
with it, and a `running`, locked, or already-archived run is refused
regardless. Finished runs behave exactly as before.

### Detailed instructions

- In `src/domain/events.ts`, add `readonly force: boolean` to
  `RunArchiveRequested` (required, not optional — no back-compat shim).
- In `src/domain/reducer.ts`, rewrite the `RunArchiveRequested` case:
  - `review_open`, `completed` → `handled({ run: "archived" }, effects)` as
    today, regardless of `force`.
  - `created`, `failed`, `interrupted`, `rate_limited`, `stopped` →
    `event.force` ? the same `handled(...)` : `rejected("run is <state>, not
    finished; pass --force to archive it anyway")` (wording indicative; it must
    contain the state name and `--force`).
  - `archived` → `rejected("run is already archived")` (unchanged).
  - `running` → `rejected("cannot archive a running run")` regardless of
    `force`.
  Keep the exhaustiveness `default: assertNever(state)`. Factor the effects
  list once so the two `handled` branches share it.
- In `src/domain/errors.ts`, add
  `ArchiveRefusedError extends Data.TaggedError("ArchiveRefusedError")<{ message: string; shortName: string; state: string }>`.
- In `src/app/archive.ts`:
  - Pass `force: opts.force ?? false` in the dispatched event.
  - Compute `finished = runState === "review_open" || runState === "completed"`
    from `infoResult` (treat a Left as not finished) and run the existing
    final-worktree dirty check only when `!opts.force && finished`.
  - When `result.disposition !== "Handled"`, fail with `ArchiveRefusedError`
    built from `result.stateBefore.run` and the disposition's `reason`
    (`Run "<qualifiedKey>" <reason>.`) instead of `InvalidTransitionError`.
    Drop the `InvalidTransitionError` import if it becomes unused; keep it in
    the error union only if still thrown.
  - Update the step-4 comment to describe the widened rule.
- Update every other constructor of the event literal to include `force`:
  `tests/unit/events.test.ts` (sample, `force: false`),
  `tests/integration/dispatcher.test.ts:198` (`force: false`),
  `tests/integration/archive.test.ts:198,229` (`force: false`),
  `tests/unit/reducer.test.ts` `sampleEvents.RunArchiveRequested`
  (`force: false` so the matrix walker still agrees without touching
  `src/domain/matrix.ts`).
- Reducer unit tests (`tests/unit/reducer.test.ts`), one `it` per case:
  - for each of `created`, `failed`, `interrupted`, `rate_limited`, `stopped`:
    `force: false` → `Rejected` whose reason contains the state name and
    `--force`; `force: true` → `Handled` with `run: "archived"` and the same
    `MoveRunToArchive` effects as the finished path (both with and without the
    worktrees pair).
  - `running` with `force: true` → `Rejected`.
  - `archived` with `force: true` → `Rejected` with reason
    `run is already archived`.
  - `review_open` and `completed` with `force: false` → `Handled` (unchanged
    behaviour pinned).
- Use-case integration tests (`tests/integration/archive.test.ts`): widen
  `seedFs`'s `runState` to the full `RunState` union and add a `describe`
  block "archive — unfinished runs":
  - each unfinished state without `force` → Left `ArchiveRefusedError`, its
    message names the state and `--force`, `run-status.json` still reports the
    original state, registry entry unchanged, no `MoveRunToArchive` emitted.
  - each unfinished state with `force: true` → run folder and worktrees folder
    (when seeded) land under `archive/<qualifiedKey>/{runs,worktrees}`,
    registry entry `archived` with `archivePath` set, `pruneWorktrees` called.
  - `created` with no worktrees dir and `force: true` → only the run folder
    moves.
  - `interrupted` with a dirty phase-01 worktree (fake git reports not clean)
    and `force: true` → archived; the same seed without `force` → refused with
    the state message, not the dirty-worktree message.
  - `running` with `force: true` → Left, state unchanged.
  - active lock with `force: true` → `LockConflictError` naming the pid.
  - `archived` with and without `force` → Left, message says already archived.
  - a `rate_limited` seed with `stoppedReason` and `lastError` → after forced
    archive, the run-status under the archive path carries both values verbatim.
  - `review_open` with a dirty final worktree and no `force` → still
    `ArchiveBlockedByDirtyWorktreeError` (regression pin for §5.1).

### Boundary contracts

- **CLI → use case.** The consumer (`runArchive` in the CLI command) keeps
  passing `{ force?: boolean }`; the producer (`archive()`) now fails with
  `ArchiveRefusedError` for every state-based refusal and

  needed in this phase.

  whether consent was given (`force`); the reducer is the sole owner of which
  states that consent unlocks.

feat(archive): archive unfinished runs with --force consent

### Commit body

Widen the run state machine's archive rule: RunArchiveRequested carries a
required `force` consent, and the reducer archives created, failed,
interrupted, rate_limited and stopped runs only when it is set, rejecting
otherwise with a reason naming the state and --force. running and archived
stay refused regardless. The archive use case passes the flag, applies the
final-worktree dirty guard to finished runs only, and surfaces every rejected
dispatch as ArchiveRefusedError. Covered by per-state reducer and use-case
tests, including stop-reason preservation and lock refusal. Implements spec 32
§5.1–§5.7.
