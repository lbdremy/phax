# Command contracts

## 1. Context

phax's 65 commands are Commander commands, each written by hand in src/cli/program.ts or a register function, each printing what it chooses. Nine have a `--json` option, each with its own help text and its own meaning: `ls --json` prints the versioned `run-list` document; `plans overview --json` and `plans lint --json` print an unversioned object; `artifact decide --json` works only with `--verdicts`; `prune --json` also means "never prompt". `artifact status` has none. Unknown options and commands are refused by Commander with exit 1; an unexpected crash prints `Unexpected error: …` and exits 1; the phase guard refuses with exit 1. The documented codes (2 invalid config or plan, 3 unsafe git state, 4 gate, 5 agent, 7 lock, 12 artifact refusal, 14 network, …) come from mapping phax's tagged errors.

`phax.usage.kdl` is the contract of the command line. A script walks the live Commander tree to write it, adding the long help and examples from a side table (cliDocs) and the `complete` nodes from another (cliCompleters: run short names come from `phax ls --complete`). `phax --usage` prints it; a parity gate checks it matches the tree.

Outside this repository the operator wrote a command library (TypeScript on Effect 4, with a Rust twin passing the same conformance cases): a command declares its sources (args, flags, stdin, env) as schemas with a reject or strip policy, an output contract, an exit code per tagged error, a `run`, an optional `render`, `notes`, a `document` hook and `writesDocument`; groups hold commands under one word; a program names its `refused` and `defect` codes; the runner over Commander decodes, runs, encodes, forces `--json` (output on stdout, message lines on stderr), prints contracts with `--json-schema`, and writes the usage spec in KDL from the definitions. The operator brings it under phax's Apache-2.0 licence and settled on 2026-10-30, 2026-11-02 and 2026-11-03 that phax ports it to Effect 3 and moves every command onto it.

Ground read:

- `docs/briefs/command-contracts.md` — The operator's brief: the library as of 2026-11-03, the seven settled points, what the library lacks for phax.
- `docs/briefs/claude-code-mod.md` — The consumer this spec is the prerequisite of: it reads artifact status, plans overview and the run list as versioned JSON only.
- `src/cli/program.ts` — Every command is a Commander command built here or in a register*Command function; the preAction hook answers --usage and runs the phase guard (exit 1); cliDocs is applied as after-help text.
- `src/cli/main.ts` — --usage is caught before Commander parses; an unexpected error prints `Unexpected error: …` and exits 1.
- `src/cli/commands/plans.ts` — plans lint prints its report (JSON.stringify, unversioned) and exits 1 when a finding is an error, 2 on an invalid config.
- `src/cli/commands/plansOverview.ts` — plans overview --json prints the PlanOverview unversioned; the architecture warning goes to stderr in both modes.
- `src/cli/commands/artifact.ts` — artifact status is text only: Path, Kind, Status, Authored, Questions, Approved, Edited since, Legal transitions; artifact new spec|plan and agent setup are three words deep; --brief and --verdicts take <file|->; decide refuses --json without --verdicts.
- `src/cli/commands/ls.ts` — ls --json prints the versioned run-list document; ls --complete prints `short-name:state` lines for shell completion.
- `src/schemas/runList.ts` — The run-list row: qualifiedName, namespace, shortName, state, branch, currentPhase, gateProfile, updatedAt, lockState, recordsPending, archivePath, stop; strict keys.
- `src/schemas/publication.ts` — A run's publication records pullRequestUrl when phax opened the pull request.
- `scripts/generate-usage-spec.ts` — phax.usage.kdl is generated by walking the live Commander tree, with cliDocs for long help and examples and cliCompleters for complete nodes.
- `src/cli/cliCompleters.ts` — One completer: short-name, run by `phax ls --complete`, with descriptions.
- `src/cli/introspect.ts` — The parity snapshot walks Commander, skipping hidden commands and retired options.
- `src/cli/commands/runLayers.ts` — exitCodeForError maps phax's tagged errors to the documented codes 1–14; 64 and 70 are used by no command.
- `src/schemas/schemaUrl.ts` — Published formats are named https://docs.phax.run/schemas/<format>/<release>.json.

## 2. Problem

Nothing an agent reads from phax is guaranteed. Whether a command has `--json`, what it means, whether the document is versioned, what reaches stderr, and how a failure looks are each command's private choice: 56 commands have no machine answer at all, two of the nine that do print an unversioned object, and the errors are English sentences an agent must parse. The Claude Code mod (brief `claude-code-mod`) can only read versioned JSON validated against published schemas, and today three of the four things it needs — `artifact status`, `plans overview`, and the run's pull request — are text, unversioned or missing.

The command line's contract is also held together by side tables: help and examples in cliDocs, completers in cliCompleters, the usage spec rebuilt by walking a Commander tree that every command file builds by hand. Nothing ties a command's declared input to what it decodes, nor its documented codes to what it can fail with.

## 3. Product goal

Every phax command runs under one contract — what it reads, what it answers, how it fails — through the ported command library, so that `--json` gives an agent the same thing on every command: the output contract's JSON on stdout and message lines on stderr, with the contracts themselves printable by `--json-schema`. The three answers the Claude Code mod needs come first: `artifact status --json` (new, versioned), `plans overview --json` and `plans lint --json` (versioned), and `ls --json` carrying each run's pull request. A person sees the same text as today, and the command line declares the same commands, arguments, options and codes.

> An agent can rely on any phax command's answer without reading its source, and a person notices nothing but a new flag.

## 4. Terminology

- **command library** — The operator's library defining what a command, a group and a program are, their two policies, the written-file record, the contracts catalogue, the usage spec, the message lines and a conformance suite; and its one runner, over Commander. Here: its port to Effect 3 inside phax.
- **port** — The copy of the command library in phax's own source, on Effect 3, changed only where Effect 3 asks or by a gain.
- **gain** — A capability phax needs that the library lacks, added to the port written as the library would carry it, so it can go upstream.
- **output contract** — The schema of the value a command answers with; its encoded form is what `--json` writes on stdout.
- **render** — A command's optional pure function from its output (and the terminal) to the text a person reads without `--json`.
- **message line** — Under `--json`, one compact JSON object on one stderr line, tagged by `kind`: `note`, `written`, `error`, `refused` or `defect`.
- **document** — A JSON value carrying `$schema` first, naming its published format and the release that shapes it.
- **written-file record** — `{ path, format, digest }` for a file a command wrote: path from the repository root, the document's `$schema` or null, and `sha256:` plus 64 lowercase hex digits.
- **refused** — The program's code for a call no command can accept: unknown command, undeclared argument or option, a source or document that does not decode, a stdin read while stdin is a terminal.
- **defect** — The program's code for what no command declared: a death, an output that does not encode, a misdeclared program.
- **verdict code** — A non-zero exit code a command declares its successful output may answer with (gain from the Rust twin); the output is written all the same.
- **contracts catalogue** — What `phax --json-schema` prints: `program`, `version`, `exits` (refused, defect), `commands` (each with name words, input, stdin, output, errors) and `messages`, all JSON Schema 2020-12.
- **group** — A word holding commands or (gain) other groups, e.g. `artifact`, `artifact new`; called alone it writes its help and is refused.
- **stdin flag** — A flag a command binds to its stdin source, naming the document it reads (`--verdicts`, `--brief`).

## 5. Functional requirements

### 5.1 Every command under the runner

The system shall register every phax command and group through the ported command runner, so that no command definition reaches the argument parser directly.

### 5.2 --json writes the output contract

WHEN any command succeeds with `--json` THE system SHALL write on stdout its output's encoded form, never its render's text, indented by two spaces with one trailing newline and `$schema` first when the output has one.

### 5.3 --json keeps stderr to message lines

WHILE a command runs with `--json` THE system SHALL write on stderr only message lines, one compact JSON object per line tagged `note`, `written`, `error`, `refused` or `defect`, none carrying a `$schema`.

### 5.4 Text for a person stays

WHEN a command succeeds without `--json` THE system SHALL write its render's text, or its output's encoded form when it has no render, and the text a person reads from an existing command shall be what phax prints for it today.

### 5.5 Error sentences stay

IF a command fails with a declared error without `--json` THEN the system SHALL write that error's sentence for a person on stderr, as phax words it today, and exit with that error's code.

### 5.6 Documented codes stay

The system shall exit with the code each command documents today for each of its outcomes, in both modes.

### 5.7 An answer with a code

WHEN a command's output answers with a verdict code it declares THE system SHALL write that output in either mode and exit with that code.

### 5.8 Refused calls

IF a call names an unknown command, an undeclared argument or option, or a source or document that does not decode THEN the system SHALL refuse it before any command runs, exiting with the program's `refused` code and, under `--json`, writing one `refused` line naming the source and the field that failed.

### 5.9 Defects

IF a command dies with what it did not declare, or its output does not encode THEN the system SHALL write a `defect` line under `--json` or `defect: …` text without it, and exit with the program's `defect` code.

### 5.10 A misdeclared program runs nothing

IF the program's `refused` and `defect` codes collide, a command declares the `defect` code, or a command declares an option `json` or `json-schema` (or `out` beside writing one document) THEN the system SHALL run no command, name the offending command, and exit with the `defect` code.

### 5.11 Nested groups

WHEN a group is called alone, at any depth (`phax artifact`, `phax artifact new`, `phax agent setup`) THE system SHALL write its help on stderr and refuse the call.

### 5.12 A command's contracts

WHEN a command is called with `--json-schema` THE system SHALL print that command's catalogue entry — name words, input, stdin, output and errors as JSON Schema 2020-12 — and run nothing.

### 5.13 The contracts catalogue

WHEN `phax --json-schema` runs THE system SHALL print the contracts catalogue, whose entry for each command equals what that command's `--json-schema` prints.

### 5.14 A document behind a flag

WHERE a command binds a flag to its document THE system SHALL read the file the flag names, or stdin when its value is `-`, and SHALL not open stdin when the flag is absent.

### 5.15 Never wait on a terminal

IF a command would read its document from stdin while stdin is a terminal THEN the system SHALL refuse the call at once, naming the flag, without waiting for input.

### 5.16 A bad document is refused before run

IF a document's file cannot be read, is not what its contract reads, or does not decode THEN the system SHALL refuse the call before the command runs, naming the path or stdin and the field that failed.

### 5.17 A text document

WHERE a command's document is text, as the Markdown brief of `phax artifact new spec|plan --brief`, THE system SHALL hand the command the text as read, under the same reading and refusal rules as a JSON document.

### 5.18 Written files are part of the answer

The system shall report each file a command writes as a written-file record, in its output on success and in its error's `written` when it fails part way, and under `--json` as one `written` line per file of a document answer.

### 5.19 Progress as it goes

WHILE a command that reports progress (`run`, `resume`, `artifact decide`, the authoring and review sessions) runs with `--json` THE system SHALL write each progress line as a `note` line at the moment it happens.

### 5.20 --json never waits on a person

IF `--json` is given to a command in a mode that prompts or hands the terminal to an interactive session THEN the system SHALL refuse the call before anything starts.

### 5.21 The usage spec from the definitions

The system shall write `phax.usage.kdl` from the command definitions — help, long help, examples, arguments, options, defaults, choices, completers and `--json` — and what each command declares in it shall not change.

### 5.22 phax --usage stays

WHEN `phax --usage` runs, with or without `--usage-format`, THE system SHALL print the usage spec as it does today.

### 5.23 Help and version stay text

WHEN `--help` or `--version` is given THE system SHALL answer in text, the help of every command listing `--json`.

### 5.24 artifact status --json

WHEN `phax artifact status <path> --json` runs THE system SHALL write an `artifact-status` document: path, kind, status, legal transitions, approval with its approver and whether the artifact was edited since, authoring mode with sidecar agreement, and the open and arbitrated questions.

### 5.25 plans overview --json versioned

WHEN `phax plans overview <plan> --json` runs THE system SHALL write a `plan-overview` document, `$schema` first and its other fields as today.

### 5.26 plans lint --json versioned

WHEN `phax plans lint <plan> --json` runs THE system SHALL write a `plan-lint` document, `$schema` first and its other fields as today, exiting 1 when a finding is an error.

### 5.27 The run's pull request in the run list

WHEN `phax ls --json` runs THE system SHALL give each run row the URL of the pull request phax opened for it, or null when it opened none.

### 5.28 Versioned documents stay

The system shall write every document that is versioned today byte for byte as today, other than the run list's new pull-request field.

Summary: Every phax command answers with JSON on stdout when given `--json`, so an agent or script can read any command the same way.

## 7. Non-goals

- phax's move to Effect 4 and the replacement of the port by the published package: a later spec.
- Publishing the library package itself.
- The Claude Code mod.
- A flag that only validates the input and stops.
- `--help` and `--version` in JSON: they stay text.
- Renaming a command: `phax ls` stays `phax ls` (the brief `claude-code-mod` calls it `runs list`).
- Changing the text a person reads, the commands, arguments and options a command declares, or any documented exit code.
- Changing any document versioned today, other than the run list's pull request.

## 8. Acceptance criteria

### No command reaches the parser

Given phax's source after this change, when the architecture audit runs, then no file under the command definitions imports Commander; only the ported runner does. (refs §5.1)

### --json on every command

Given every command listed in `phax --usage`, when each is called with valid input and `--json`, then stdout parses as one JSON value, indented by two spaces with one trailing newline and `$schema` first when the output has one, and every stderr line parses as a message line whose `kind` is note, written, error, refused or defect. (refs §5.2, §5.3)

### Text output unchanged

Given the existing tests that check a command's text output, when they run against the migrated command without `--json`, then they pass unchanged. (refs §5.4)

### Error sentences and codes kept

Given a run `garden-sync` locked by a live process, when `phax resume garden-sync` runs without `--json`, then with `--json`, then the first writes today's lock sentence on stderr and exits 7; the second writes an `error` line with `"error":"LockConflictError"` and `"exit":7` and exits 7. (refs §5.5, §5.6, §5.3)

### plans lint answers and exits 1

Given a plan with one error finding, when `phax plans lint <plan> --json` runs, then without `--json`, then both write the report (a `plan-lint` document with `$schema` first, then today's text) and both exit 1; a clean plan exits 0. (refs §5.7, §5.26)

### Unknown option refused

Given any command, when it is called with an undeclared option, with and without `--json`, then nothing runs, the exit code is the program's `refused` code, and under `--json` stderr holds one `refused` line with `"source":"flags"`. (refs §5.8)

### A crash is a defect

Given a command whose run dies with an undeclared failure (a test double), when it runs with and without `--json`, then it exits with the `defect` code, writing a `defect` line under `--json` and `defect: …` text without it. (refs §5.9)

### A misdeclared program runs nothing

Given a program whose command declares an option `json`, or an error code equal to `defect`, when any command of it is called, then no command runs, stderr names the offending command, and the exit code is `defect`; phax's own program passes this check in its tests. (refs §5.10)

### Groups alone at any depth

Given the groups `artifact`, `artifact new` and `agent setup`, when each is called alone, then its help is written on stderr and the call exits with the `refused` code, while `phax artifact new spec garden-sync` and `phax agent setup providers` still run. (refs §5.11)

### A command's --json-schema

Given `phax plans lint`, when `phax plans lint --json-schema` runs, then it prints an entry with `"name":["plans","lint"]`, `input`, `stdin` null, `output` and `errors`, runs no lint, and the entry equals the `plans lint` entry of `phax --json-schema`. (refs §5.12, §5.13)

### The contracts catalogue

Given phax 0.34.0, when `phax --json-schema` runs, then it prints `program` "phax", `version` "0.34.0", `exits` with `refused` and `defect`, one entry per command in `phax --usage`, and `messages` with the five message line shapes. (refs §5.13)

### A document from a file or stdin

## 9. Open questions

### q-program-codes — Which codes do the program's `refused` and `defect` take? Today both an unknown option and a crash exit 1, which phax documents nowhere; `defect` cannot be 1 because commands answer with 1.

- sysexits — `refused` 64 (EX_USAGE) and `defect` 70 (EX_SOFTWARE), both documented in `phax --usage` and the exit-codes reference — abandons: the exit 1 a script sees today on a mistyped call, undocumented but observable
- keep-one — `refused` stays 1 and `defect` takes 70 — abandons: telling a refused call from a command's own failure by its code: 1 is already the failure code of a dozen commands and of `plans lint`'s error verdict

Recommendation: sysexits — The code exists for an agent to act on, and the first thing it must know is whether to fix its call or the world; with `refused` at 1 it cannot. The lost exit 1 was never documented, and 64 and 70 are used by no phax command.

### q-stdin-flag-value — The library's stdin flag takes an optional value attached (`--verdicts`, `--verdicts=-`, `--verdicts=<path>`); phax's `--verdicts <file|->` and `--brief <file|->` take a required value, often spaced (`--verdicts verdicts.json`). Which form does the port carry?

- keep-value — A gain: the stdin flag may declare its value required, `<file|->`, spaced or attached; phax's two flags keep today's declaration — abandons: the library's single form of a stdin flag: the published package must take the variant upstream, or phax changes later
- library-form — Adopt the library's optional attached value for `--verdicts` and `--brief` — abandons: settled point 4 for two flags: `phax --usage` changes and every spaced `--verdicts verdicts.json` or `--brief brief.md` in docs, skills and habits becomes a refused call

Recommendation: keep-value — Point 4 makes the command line's declarations the contract, and the brief `claude-code-mod` and the decide skill already invoke `--verdicts -`; a small upstreamable gain costs less than breaking every spaced invocation.

## 10. Implementation-planning note

Settled:

- Ported, not depended on: the contract and its Commander runner are ported to Effect 3 into phax's own source with the conformance suite, keeping the library's export names and its split into a contract and a runner, so that swapping in the published package is an import change. phax's commands import the port, never Commander.
- The library's rules (output contract, `--json` layout, message lines and their fields, `--json-schema` catalogue and entries, stdin source and stdin flag, written-file records, `document` hook, `writesDocument` and `--out`) are taken as they are; the spec restates only what phax must observe.
- Gains the port makes, each written as the library would carry it: groups holding groups; completers declared on an argument and written as `complete` nodes by the usage spec; verdict codes, from the Rust twin; a text stdin document; progress notes written while `run` runs; a declared error's text form for a person; the program naming its usage flag (`--usage`, `--usage-format`) instead of the hidden `--usage-spec`; program-wide options (`--verbose`, `--trace`).
- Under `--json`, a declared error's line carries the library's fields only (tag, exit, fields, written); the sentence for a person is written only without `--json`.
- A mode that prompts or hands the terminal to a session refuses `--json`, as `artifact decide` refuses `--json` without `--verdicts` today; under `--json`, `prune` never prompts, as today.
- Every command moves in this spec; `artifact status`, `plans overview`, `plans lint` and `ls` come first.

Left open:

- The order of the remaining command families, and how many phases.
- Each command's output contract and whether it has a render; a command that writes files answers with their written-file records.
- Which commands answer with a document (`document` hook) and which write exactly one and so take `--out`.
- Whether `--json-schema` is listed per command in the usage spec, as the library does.
- The `artifact-status` field spellings and the run-list field name (`pullRequest`), within §6.

Constraints:

- `phax ls --complete` keeps printing `short-name:state` lines: the shell completer runs it.
- The phase guard keeps refusing inside a phase worktree, with exit 1, before any command runs; under `--json` it is a message line like any other.
- `phax.usage.kdl` is written by the library's usage spec from the definitions, called by the generator script; cliDocs moves into each command's `help` and `examples`, each argument's and option's help into its schema's annotations, cliCompleters into the arguments; the parity gate becomes: the file is the generator's output.
- The new formats `artifact-status`, `plan-overview` and `plan-lint`, and `run-list` with its pull request, are exported, snapshotted and published through `packages/schemas` at 0.34.0, like every other format.
- The `refused` and `defect` codes are documented in `phax --usage` and in the exit-codes reference.
- No back-compat shim: the new `pullRequest` key is required (null when none); the unversioned objects of `plans overview` and `plans lint` are replaced, not kept beside the documents.
