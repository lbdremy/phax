# Prune archived runs

## 1. Context

A phax run lives in several places. Its run folder is ~/.phax/runs/<namespace>.<short-name>/ and its worktrees are under ~/.phax/worktrees/<namespace>.<short-name>/. It has one entry in ~/.phax/registry.json. The project repository holds its git state: the run branch (the entry's `branch`, e.g. `phax/<short-name>`), one branch per phase named `<branch>--phase-NN` (each branched off the one before), and the git metadata for its worktrees. A published run also has a remote branch and a pull request. Every run writes records to the `phax/records/v1` branch, keyed by run id rather than by name.

`phax archive <short-name>` moves the run folder and the worktrees into one folder, ~/.phax/archive/<namespace>.<short-name>/{runs,worktrees}. It then runs `git worktree prune` in the current repository and sets the registry entry to `state: "archived"` with an `archivePath`. It deletes nothing and leaves branches alone. A qualified name (<namespace>.<short-name>) lets archive reach a run in another namespace, but its git cleanup only touches the current repository: the louloupapers runs needed a manual `git worktree prune`. The registry entry does not record which repository a run belongs to.

A new run takes its short name from the plan slug. `phax run` treats a name as taken while any registry entry in the same namespace holds it, archived ones included, and appends -2, -3, … until it finds a free name. When the run branch or a phase branch already exists locally, `phax run` reuses it instead of creating it. `publish-pr` pushes the final phase branch without force.

`phax ls` lists the registry, with `--archived` and `--json`. No command deletes a run. On the author's machine today: 123 registry entries, all archived; ~/.phax/archive holds 86 GB; 22 runs carry a -2-style suffix; the phax repository alone has 375 local `phax/<name>--phase-NN` branches left by past runs.

Ground read:

- `NEXT_STEPS.md` — Road to 1.0.0 "`phax prune`" and Spec candidates "`phax prune` — delete archived runs" (raised 2026-09-08). Housekeeping note: archiving another namespace's runs only runs `git worktree prune` in the current repository.
- `src/app/archive.ts` — What archive does: moves the run folder and the worktrees under ~/.phax/archive/<namespace>.<short-name>/{runs,worktrees}, runs `git worktree prune` in the current repository only, and sets the registry entry to state archived with archivePath. It never touches branches.
- `src/cli/commands/archive.ts, src/app/resolveRunRef.ts` — A run is named by its short name, or by its qualified name <namespace>.<short-name>. A qualified name can reach a run in another namespace.
- `src/schemas/registry.ts, src/app/registry.ts` — Registry entry shape: namespace, shortName, runId, state, branch, projectName, phasesCount, createdAt, updatedAt, optional archivePath. The entry does not record which repository the run belongs to. The registry can be read, upserted and status-patched; nothing removes an entry today.
- `src/cli/commands/run.ts (ensureUniqueShortName)` — A name counts as taken when any registry entry in the same namespace holds it, archived ones included, or when a bare folder with that name exists. The next free name gets a -2, -3, … suffix.
- `src/app/worktree.ts (prepareRunBranch, preparePhaseBranch)` — When the run branch or a phase branch already exists locally, `phax run` reuses it as is instead of creating it.
- `src/infra/git.ts (pushBranch, deleteBranch)` — `publish-pr` pushes without force (`git push --set-upstream`). A branch is deleted with `git branch -d|-D`.
- `phax.usage.kdl` — cmd archive; cmd ls (--archived, --json, --complete); `--yes -y` on resume and reset-phase (reset-phase removes a worktree and a branch). The CLI contract is generated from Commander.
- `README.md` — § Archive ("Archive is the only operation that touches worktrees/"), § Exit codes (0,1,2,3,4,5,6,8,9), § Persisted formats (the run registry is a public format of @lbdremy/phax-schemas).

## 2. Problem

An archived run never goes away, so it holds its short name forever. Name uniqueness is right and stays. That leaves one way to reuse a slug — delete the run that holds it — and phax has no command for that. The results: the -2 habit (22 runs), 86 GB of archived worktrees that can only be reclaimed by hand, and hundreds of stale phase branches.

Deleting by hand is unsafe, and not obviously so. Removing the archive folder and the registry entry frees the name. But if `phax/<name>` or `phax/<name>--phase-NN` survives locally, the next run with that name silently builds on the old run's branches, because `run` reuses existing branches. Deleting those branches blindly can destroy commits that exist nowhere else. The run lifecycle also has no end: created → … → archived, and then nothing.

## 3. Product goal

Give the operator one command, `phax prune`, that deletes archived runs for real: the archive folder, the worktree metadata, the local branches and the registry entry. Pruning frees the run's name and returns its disk space. By default it never destroys a commit that no other ref keeps, and it never touches the run's lasting history (its records), its remote branches or its pull request. This closes the run lifecycle: created → … → archived → gone. `archive` moves and keeps; `prune` removes.

> prune frees a name only once nothing of the run that `phax run` could trip over is left locally, and it never destroys an unpreserved commit unless the operator forces it.

## 4. Terminology

- **Archived run** — A registry entry with `state: "archived"`. Its run folder and worktrees sit in its archive folder, ~/.phax/archive/<namespace>.<short-name>/.
- **Prune** — Delete an archived run for real: its archive folder, its worktree metadata, its local branches and its registry entry. Distinct from archive, which moves and keeps.
- **Current namespace** — The namespace of the phax project whose config loads from the working directory.
- **The run's local branches** — In the current repository: the registry entry's `branch` (e.g. `phax/old-idea`) plus every local branch named `<branch>--phase-NN`. Slugs cannot contain `--`, so `phax/old-idea-2--phase-01` is never a branch of `old-idea`.
- **Unpreserved commit** — A commit that one of the run's local branches reaches and that no ref outside the branches this command is about to delete reaches — no other local branch, tag or remote-tracking ref. A run's own phase branches, and the branches of the other runs selected in the same command, do not preserve each other. Deleting the run's branches would lose it.
- **Worktree metadata** — Git's records of the run's worktrees in the current repository — the entries `git worktree list` shows.
- **Kept run** — A selected run that this invocation did not prune. Its registry entry remains, so its name stays held.
- **Remote-tracking ref** — A ref such as `origin/phax/old-idea--phase-03`, as the local repository last fetched it. prune reads these refs and never contacts a remote.

## 5. Functional requirements

### 5.1 Selection by name

The `phax prune` command shall select the runs named by its positional arguments, resolved in the current namespace. Each argument is a short name or a qualified name `<namespace>.<short-name>`.

### 5.2 Selection of every archived run

WHERE `--all` is given THE system SHALL select every registry entry of the current namespace whose state is `archived`.

### 5.3 Exactly one selection form

IF `phax prune` is given neither a run name nor `--all`, or is given both, THEN the system SHALL refuse with exit code 1 before deleting anything, naming the two accepted forms.

### 5.4 Project required

IF `phax prune` runs where no phax project config loads THEN the system SHALL refuse with exit code 1 before deleting anything.

### 5.5 Archived runs of the current namespace only

IF a named run is not in the registry, is not in the `archived` state, or belongs to a namespace other than the current one, THEN the system SHALL refuse the whole command with exit code 1 before deleting anything, naming each offending run with its reason: not found, its state, or its namespace.

### 5.6 Locked runs

IF any selected run holds an active lock THEN the system SHALL refuse the whole command with exit code 7 before deleting anything, naming the run and `phax unlock`.

### 5.7 What a prune deletes

WHEN a selected run is pruned THE system SHALL delete its archive folder, its worktree metadata in the current repository, its local branches, and its registry entry.

### 5.8 What a prune never touches

The `phax prune` command shall leave untouched the `phax/records/v1` branch, every remote branch, every remote-tracking ref, every pull request, and every local branch that does not belong to a selected run.

### 5.9 Unpreserved commits keep the run

IF a selected run's local branches hold at least one unpreserved commit THEN the system SHALL keep that run, delete none of its parts, and report each branch holding unpreserved commits with their count.

### 5.10 Discarding unpreserved commits

WHERE `--force` is given THE system SHALL prune a run whose local branches hold unpreserved commits, reporting each discarded branch with its unpreserved-commit count.

### 5.11 Checked-out branches keep the run

IF one of a selected run's local branches is checked out in any worktree of the current repository THEN the system SHALL keep that run and delete none of its parts, even with `--force`, reporting the branch and the worktree path.

### 5.12 Preview before deletion

WHEN `phax prune` has resolved its selection THE system SHALL print, before deleting anything, one line per selected run. Each line gives the planned outcome (prune or keep), the size of the archive folder, and either the local branches it will delete or the reason it will keep the run.

### 5.13 Preview only

WHERE `--dry-run` is given THE system SHALL print the preview and exit 0 without deleting anything or asking for confirmation.

### 5.14 Interactive confirmation

WHILE stdin is a TTY, neither `--yes` nor `--dry-run` is given, and at least one run is planned for pruning, THE system SHALL ask for confirmation after the preview and delete nothing unless the operator answers yes.

### 5.15 No silent deletion without a TTY

IF stdin is not a TTY and neither `--yes` nor `--dry-run` is given THEN the system SHALL print the preview, delete nothing, and exit 1, naming `--yes`.

### 5.16 Outcome report

WHEN `phax prune` finishes deleting THE system SHALL print one line per selected run with its outcome (`pruned` or `kept`), the bytes freed and the local branches deleted, followed by a total of runs pruned and bytes freed.

### 5.17 Surviving remote branches

WHEN a pruned run still has remote-tracking refs for its branches THE system SHALL list them as kept and warn that a future run with the same name will meet them when it publishes.

### 5.18 Idempotent removal

IF a part of a selected run — its archive folder, its worktree metadata, or one of its local branches — is already absent THEN the system SHALL count that part as removed, report it as already absent, and continue.

### 5.19 Partial failure

IF a part of a selected run cannot be removed THEN the system SHALL keep that run's registry entry, report the part and the reason on one line without a stack trace, and continue with the remaining runs.

### 5.20 Exit codes

The `phax prune` command shall exit 0 when every selected run was pruned (or there was nothing to prune), 3 when at least one selected run was kept, 1 when it deleted nothing because the command was refused or the confirmation was declined or missing, and 7 on a lock conflict — the codes `exitCodeForError` gives these families in every other command.

### 5.21 The README exit-code table is the code's

The README's exit-code table shall list every exit code `exitCodeForError` and the commands return, with the meaning the code gives it, and phax's test suite shall fail when the table and the code disagree.

### 5.22 Machine-readable output

WHERE `--json` is given THE system SHALL write a single JSON document to stdout in place of the human output. The document carries each selected run's outcome, size and branches, plus the totals. With `--json` the system SHALL never prompt.

### 5.23 Registry format unchanged

The `phax prune` command shall remove registry entries without changing the registry format and without changing any field of an entry it does not prune.

### 5.24 The name is free afterwards

WHEN a run has been pruned THE system SHALL treat its short name as free, so that the next `phax run` in that namespace whose base name is that short name receives it without a numeric suffix.

## 6. Surface

### cli: phax prune — normative

    phax prune <short-name>... [--force] [--dry-run] [--yes | -y] [--json]
    phax prune --all           [--force] [--dry-run] [--yes | -y] [--json]

      <short-name>   an archived run of the current namespace, short or qualified (<namespace>.<short-name>)
      --all          every archived run of the current namespace
      --dry-run      print the preview, delete nothing
      --yes, -y      proceed without confirmation (required without a TTY)
      --json         machine-readable output; never prompts

    Normative: the command name, the variadic positional, --all, --dry-run, --yes/-y and --json. --force is a separate element below.

## 7. Non-goals

- The preflight-before-naming fix (a run that burns its slug before preflight). That is a separate spec.
- Deleting or rewriting records on `phax/records/v1`, or changing any `records` command.
- Deleting remote branches, remote-tracking refs or pull requests, and any network access (no fetch, no push, no GitHub call).
- Automatic pruning, retention policies, age or pattern filters such as `--older-than`, and pruning as a side effect of `archive`.
- Pruning runs of another namespace, pruning from outside a phax project, or reaching any repository other than the current one.
- Pruning runs that are not archived: archive them first.
- Changing how `phax run` treats existing local or remote branches, or how `publish-pr` pushes.
- Any persisted-format change, including recording a run's repository path in the registry.
- Undo, trash or soft delete: a pruned run is gone.
- Cleaning up stray `phax/*` branches that belong to no registry entry.

## 8. Acceptance criteria

### An archived run is deleted for real

Given an archived run `old-idea` in the current namespace whose local branches `phax/old-idea` and `phax/old-idea--phase-01..03` all point at commits reachable from `main`, when `phax prune old-idea --yes` runs, then its archive folder, its registry entry and all four local branches no longer exist, `git worktree list` shows none of its worktrees, and the command exits 0. (refs §5.7, §5.1, §5.20)

### A qualified name in the current namespace is accepted

Given an archived run `old-idea` in namespace `phax` and a current namespace of `phax`, when `phax prune phax.old-idea --yes` runs, then the run is pruned exactly as `phax prune old-idea --yes` would prune it. (refs §5.1)

### --all prunes the namespace's archived runs only

Given namespace `phax` holds archived runs `a` and `b` and a `review_open` run `c`, and namespace `other` holds an archived run `d`, when `phax prune --all --yes` runs from the phax repository, then `a` and `b` are pruned, and the registry entries of `c` and `d` are field-for-field unchanged. (refs §5.2, §5.23)

### --all with nothing to prune

Given no archived run in the current namespace, when `phax prune --all` runs, then it reports that nothing is to be pruned, does not prompt, and exits 0. (refs §5.2, §5.20)

### Exactly one selection form

Given a phax project with archived runs, when `phax prune` runs with no name and no `--all`, or with both a name and `--all`, then it exits 1 naming both accepted forms, and the registry and branches are unchanged. (refs §5.3)

### Outside a project

Given a working directory where no phax project config loads, when `phax prune --all --yes` runs, then it exits 1 and the registry is unchanged. (refs §5.4)

### A non-archived run refuses the whole command

Given a `review_open` run `feature-x` and an archived run `old-idea`, when `phax prune feature-x old-idea --yes` runs, then it exits 1 naming `feature-x` and its state `review_open`, and `old-idea` is not pruned. (refs §5.5)

### An unknown name refuses the whole command

Given no registry entry named `ghost` and an archived run `old-idea`, when `phax prune ghost old-idea --yes` runs, then it exits 1 naming `ghost` as not found, and `old-idea` is not pruned. (refs §5.5)

### Another namespace is refused

Given an archived run `louloupapers.cover-flow` and the phax repository as working directory, when `phax prune louloupapers.cover-flow --yes` runs, then it exits 1 with a message naming namespace `louloupapers`, and that run's archive folder and registry entry remain. (refs §5.5)

### A locked run refuses the whole command

Given an archived run `old-idea` holding an active lock and an archived run `spare`, when `phax prune old-idea spare --yes` runs, then it exits 7 naming `old-idea` and `phax unlock`, and neither run is pruned. (refs §5.6)

### Records, remotes and neighbour branches survive

Given an archived run `old-idea` with records on `phax/records/v1`, a remote-tracking ref `origin/phax/old-idea--phase-02`, and the branches `phax/old-idea-2` and `phax/old-idea-2--phase-01` belonging to another run, when `phax prune old-idea --yes` runs, then the tip of `phax/records/v1` is unchanged, `origin/phax/old-idea--phase-02` still exists, and both `phax/old-idea-2` branches still exist. (refs §5.8)

### Unpreserved commits keep the run whole

Given an archived run `spike` whose `phax/spike--phase-02` holds 2 commits that no other ref reaches, when `phax prune spike --yes` runs, then the archive folder, the registry entry and every local branch of `spike` remain, the output names `phax/spike--phase-02` with 2 unpreserved commits, and the command exits 4. (refs §5.9, §5.20)

### A remote-tracking ref preserves commits

Given an archived run `shipped` whose final phase branch's commits are reached only by the remote-tracking ref `origin/phax/shipped--phase-03`, when `phax prune shipped --yes` runs, then `shipped` is pruned, and `origin/phax/shipped--phase-03` still exists. (refs §5.9, §5.8)

### --force discards unpreserved commits

Given the run `spike` from "Unpreserved commits keep the run whole", when `phax prune spike --force --yes` runs, then `spike` is pruned, the output reports `phax/spike--phase-02` as discarded with 2 unpreserved commits, and the command exits 0. (refs §5.10)

### A checked-out branch keeps the run even with --force

Given an archived run `old-idea` whose branch `phax/old-idea--phase-03` is checked out in the repository's main worktree, when `phax prune old-idea --force --yes` runs, then none of `old-idea`'s parts are deleted, the output names the branch and the worktree path, and the command exits 4. (refs §5.11, §5.20)

### --dry-run previews and deletes nothing

Given an archived run `a` that is prunable and an archived run `b` with unpreserved commits, when `phax prune a b --dry-run` runs, then the output has one line per run giving its planned outcome (prune / keep), its archive folder size, and either its branches to delete or the reason it is kept; nothing is deleted; no prompt appears; and it exits 0. (refs §5.12, §5.13)

### Declining the prompt deletes nothing

Given a TTY on stdin and an archived run `old-idea`, when `phax prune old-idea` runs and the operator answers no, then the preview was printed before the question, nothing is deleted, and it exits 1. (refs §5.14, §5.12, §5.20)

### Accepting the prompt prunes

Given a TTY on stdin and an archived run `old-idea`, when `phax prune old-idea` runs and the operator answers yes, then `old-idea` is pruned and the command exits 0. (refs §5.14)

### No TTY without --yes refuses

Given stdin that is not a TTY and an archived run `old-idea`, when `phax prune old-idea` runs without `--yes` or `--dry-run`, then the preview is printed, nothing is deleted, the message names `--yes`, and it exits 1. (refs §5.15)

### The report carries outcome, bytes and branches

Given an archived run `old-idea` with an archive folder of known size and 4 local branches, when `phax prune old-idea --yes` runs, then the output has a `pruned` line for `phax.old-idea` with the bytes freed (equal to the size in the preview) and the 4 branches deleted, and a closing total of 1 run pruned with the same bytes. (refs §5.16)

### Surviving remote branches are flagged

Given an archived run `old-idea` with a remote-tracking ref `origin/phax/old-idea--phase-03`, when `phax prune old-idea --yes` runs, then the output lists `origin/phax/old-idea--phase-03` as kept and warns that a future run named `old-idea` will meet it when it publishes. (refs §5.17)

### Re-running completes an interrupted prune

Given a registry entry for the archived run `old-idea` whose archive folder and local branches no longer exist, as left by an interrupted prune or a manual deletion, when `phax prune old-idea --yes` runs, then the registry entry is removed, the output reports the folder and the branches as already absent, and it exits 0. (refs §5.18)

### A part that cannot be removed keeps the entry

Given an archived run `a` whose archive folder cannot be deleted (no write permission) and a prunable archived run `b`, when `phax prune a b --yes` runs, then `a`'s registry entry remains, the output names the folder and the reason on one line with no stack trace, `b` is pruned, and the command exits 4. (refs §5.19, §5.20)

### --json emits one document and never prompts

Given an archived run `a` that is prunable and an archived run `b` with unpreserved commits, when `phax prune a b --json --dry-run` runs, and then `phax prune a b --json` runs on a TTY without `--yes`, then the first run writes stdout that parses as a single JSON document with the outcomes `would-prune` for `a` and `would-keep` (reason `unpreserved-commits`) for `b`, their sizes, branches and totals, and exits 0; the second run asks nothing, deletes nothing and exits 1. (refs §5.22)

### The registry keeps its format

Given a registry of three entries, one of them the archived run `old-idea`, when `phax prune old-idea --yes` runs, then `~/.phax/registry.json` keeps its `$schema`, still decodes with `parseRegistry` from `@lbdremy/phax-schemas`, and its two remaining entries are field-for-field unchanged, `updatedAt` included. (refs §5.23)

### The next run gets the bare name

Given an archived run `run-prune` in namespace `phax`, pruned with `phax prune run-prune --yes`, and an approved plan whose slug is `run-prune`, when `phax run --plan <that plan>` creates its run, then the run is named `run-prune` rather than `run-prune-2`, and its branch `phax/run-prune` is created fresh from the current branch instead of reusing an old tip. (refs §5.24, §5.7)

### The README exit-code table matches the code

Given the README's §Exit codes table and `exitCodeForError`, when the test suite runs, and again after a test double changes one code's meaning, then the table lists 0 to 12 with the code's meanings (1 generic, 2 plan or config validation, 3 unsafe git state, 4 gate failure, 5 agent invocation, 6 archive blocked by a dirty worktree, 7 lock conflict, 8 rate or usage limit, 9 phase had no changes, 10 registry corruption, 11 security or preflight refusal, 12 artifact lifecycle refusal) and the suite passes; a disagreement fails it, naming the code. (refs §5.21)

## 9. Open questions for implementation planning

### Q1 — What should prune do with a run's local branches (`phax/<name>` and `phax/<name>--phase-NN`)?

- Delete them. Keep the whole run when any of them holds an unpreserved commit; `--force` discards those commits — abandons: one-step cleanup of runs whose work landed by squash merge after the remote branch was deleted and fetched away: those commits read as unpreserved, so the run needs `--force`
- Never delete local branches, and free the name anyway — abandons: the correctness of the next run with that name: `phax run` reuses the surviving branches as is and silently builds on the old run's commits
- Never delete local branches, and refuse to prune a run that still has any — abandons: the command's usefulness: almost every archived run still has its branches (375 in the phax repository), so prune would refuse nearly everything
- Delete them unconditionally — abandons: work that exists nowhere else: a run abandoned before publishing loses its only copy, with no warning

Recommendation: Delete them. Keep the whole run when any of them holds an unpreserved commit; `--force` discards those commits — Decided by the author on 2026-10-03. Freeing a name while its branches survive is a silent correctness bug in `run`, and this spec may not change `run`, so the branches have to go with the name. Among the options that delete, only deletion gated on reachability never loses work by default. Its cost is that squash-merged work whose remote branch is gone reads as unpreserved. That cost is visible — the run is kept whole and reported, never half-deleted — and one flag answers it.

### Q2 — How does the operator select more than one run?

- One or more names, plus `--all` for every archived run of the current namespace — abandons: selection by age or pattern: clearing "everything older than a month" takes a script over `phax ls --archived --json`
- Names only — abandons: the cleanup that motivates this spec: 123 archived runs would mean 123 names, typed or scripted
- Names, `--all`, and an age filter such as `--older-than 30d` — abandons: a small contract before the 1.0 CLI freeze: a duration grammar, and a choice of which timestamp counts, get frozen into the CLI for a retention feature that is a non-goal

Recommendation: One or more names, plus `--all` for every archived run of the current namespace — Decided by the author on 2026-10-03. `--all` covers the one-time cleanup, and the preview with confirmation makes it safe. Age filters can be added later without breaking anything; once a duration grammar is frozen, it cannot be removed.

### Q3 — Does prune reach runs of other namespaces, whose git state lives in other repositories?

- Current namespace only; a qualified name from another namespace is refused — abandons: cleaning every repository from one place. A repository whose phax.json no longer loads (louloupapers today) cannot be pruned until its config is migrated
- Any namespace by qualified name; delete the folder and entry, and leave the other repository's git state — abandons: the safety of the freed name: the other repository keeps the run's branches, and its next run with that name silently reuses them
- Any namespace; find the owning repository through the git link inside the archived worktrees — abandons: dependability: the link exists only while the archived worktree folders carry it and the repository has not moved. The registry records no repository path to fall back on, and adding one would break the no-format-change constraint

Recommendation: Current namespace only; a qualified name from another namespace is refused — Decided by the author on 2026-10-03. prune is safe only because it inspects the run's branches in the repository that owns them, and the current repository is the only one phax can name with certainty. Running prune from each repository is the same habit that archive's git cleanup already requires.

### Q4 — How does prune guard the deletion: preview, confirmation, or both?

- Always preview; ask on a TTY; `--yes` skips the question; refuse without a TTY; `--dry-run` previews only — abandons: unattended use without a flag: scripts must pass `--yes`
- Preview by default; delete only with `--apply`, like `plans status --apply` — abandons: the house convention for destructive commands (`resume` and `reset-phase` use `--yes -y`), and a confirmation at the moment of deletion in interactive use
- Delete at once and report afterwards — abandons: any chance to see that 86 GB and 375 branches are about to go before they go

Recommendation: Always preview; ask on a TTY; `--yes` skips the question; refuse without a TTY; `--dry-run` previews only — Decided by the author on 2026-10-03. The deletion cannot be undone, and its size is the point of the command, so the operator should see it before it happens. `--yes` is already how phax spells "I know" for destructive commands, and a script pays one flag for it.

### Q5 — Which exit code reports that some selected runs were kept while others were pruned?

- Exit 3 (the unsafe-git-state family) — abandons: a code that means only git state: a filesystem failure (`removal-failed`) also exits 4, like unpreserved commits
- Exit 1 — abandons: a script's ability to tell "refused, nothing done" from "partly done, some runs kept"
- A new dedicated code — abandons: a stable exit-code table on the way to the 1.0 CLI freeze: one more family to document and hold

Recommendation: Exit 3 (the unsafe-git-state family) — Decided by the author on 2026-10-03. The usual reasons to keep a run — unpreserved commits, a checked-out branch — are git state. The rare filesystem failure is named in the output and in the JSON `kept.reason`, so the exit code does not need to carry it. Amended by the author on 2026-10-03: the question first cited the README's exit-code table, which was stale; in phax's code the unsafe-git-state family is 3 (4 is a gate failure) and a lock conflict is 7, so prune follows the code, and the README table is corrected to match it (requirement exit-table).

## 10. Implementation-planning note

Settled:

- A new command `phax prune` taking positional run names or `--all`, with `--dry-run`, `--yes`/`-y` and `--json`. It works on the current namespace only and on archived runs only.
- Deleted: the archive folder, the worktree metadata in the current repository, the run's local branches, and the registry entry, which goes last. Never touched: the records branch, remote branches, remote-tracking refs, pull requests, and branches of other runs.
- Local branches are deleted only when every commit they hold is reachable from a ref that prune keeps. Otherwise the run is kept whole unless `--force` is given. A checked-out branch keeps the run even with `--force`.
- Whole-command refusals (bad selection, outside a project, another namespace, a lock, no confirmation) happen before anything is deleted. A per-run failure keeps that run's entry and the command continues with the other runs.
- Exit codes are 0, 1, 3 and 4 as pinned in §6.
- Every §9 question was decided by the author on 2026-10-03, each on its recommended option.
- Exit codes follow `exitCodeForError` (amended 2026-10-03): 3 when a run is kept, 7 on a lock; the stale README table is rewritten from the code, with a test keeping them in sync.

Left open:

- The exact human wording, the size formatting, and the JSON field spelling. The outcome and kept-reason enum values are the intent.
- The final name of `--force`.
- How the archive folder's size is measured (disk usage or apparent size). Report one, and use it consistently in the preview, the report and the JSON.
- The deletion order among the archive folder, the worktree metadata and the branches, provided the registry entry goes last and a re-run completes an interrupted prune.

Constraints:

- Additive only: a new command. `run`, `archive`, `ls`, `publish-pr` and every other command keep their current behaviour.
- No persisted-format change. The registry, a public format of `@lbdremy/phax-schemas`, loses entries and is otherwise written exactly as today.
- All filesystem, git, lock and prompt access goes through the existing ports. The CLI command parses its arguments, calls one use case and renders the result.
- No network access: remote branches are known only through local remote-tracking refs.
- Regenerate `phax.usage.kdl` (`pnpm gen:usage-spec`) and add the cliDocs entry. Update README § Archive (its claim that archive is the only operation touching worktrees/) and § Exit codes. Update the phax-cli skill's lifecycle, where archived is no longer terminal.

## 11. Docs page

Page: README.md § Archive, renamed § Archive and prune, plus the generated CLI command reference and phax.usage.kdl

Reader: An operator whose ~/.phax/archive has grown, or whose new runs keep getting -2 names, and who wants to know what prune deletes, what it keeps, and how to run it safely.

Example: ## Archive and prune

`archive` moves a finished run aside and keeps everything. `prune` deletes archived runs for real — archive folder, worktree metadata, local branches, registry entry — so their names are free again and their disk space comes back. Records on `phax/records/v1`, remote branches and pull requests are never touched.

```bash
phax prune --all --dry-run   # see what would go, and what is kept and why
phax prune old-idea          # preview, then confirm
phax prune --all --yes       # every archived run of this repository's namespace
```

A run whose local branches hold commits no other ref keeps (no other branch, tag or remote-tracking ref) is kept whole; `--force` discards those commits. Run prune from the repository that owns the runs.
