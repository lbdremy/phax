# Cost ledger — what every Claude invocation of a run cost, recorded when it happens

## 1. Context

phax spawns `claude --print --output-format stream-json --verbose` for every agent turn of a run and keeps each stream in the run folder: `phase-NN/output.jsonl` (the phase turn), `phase-NN/fix-attempt-NN.jsonl` (each fix attempt, a `--resume` of the phase session), `phase-NN/handoff-generation.jsonl` (also a resume) and `compliance-review.session.jsonl`.

Each stream ends with a `result` event. Its `modelUsage[<model>]` carries `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens` and `costUSD` with `costBasis: "list"` — the API list price, checked to the cent against the token counts. Since Claude Code 2.1.280 (2.1.267 was not), a resumed session reports `total_cost_usd` and `modelUsage` **cumulatively** over the whole session, while `usage` stays per invocation: a handoff that cost $0.28 reports $8.99. Summing the kept streams naively over-counts by 29 % ($2,551 vs $1,975 on this machine's history).

Each stream also carries `rate_limit_event`s, from the first request on:

```json
{"type":"rate_limit_event","rate_limit_info":{"status":"allowed","rateLimitType":"five_hour",
 "unifiedWindows":{"five_hour":{"utilization":0.38,"resetsAt":1792069800},
                   "seven_day":{"utilization":0.22,"resetsAt":1792335600}}}}
```

Interleaved with assistant messages of known cost, these samples measure how much API-list cost one percent of a subscription window holds (spike `spikes/plan-estimate/`).

Run records (`phax records`, opt-in) already extract `usage` and `total_cost_usd`, from the phase's `output.jsonl` only — not from fix attempts, handoffs or the compliance review. The `plan-estimate` spec reads this ledger as its history and calibration source.

## 2. Problem

A run's real cost is scattered over provider streams whose cost fields changed meaning between Claude Code versions. Reading it back means re-deriving it from those streams with the version quirk in mind, every time, by every reader; a reader that forgets over-counts by a third, and streams lost to pruning take the cost with them. The subscription-window samples, the only measure of how much a window holds, are not kept anywhere phax reads.

## 3. Product goal

phax records, at the moment each Claude invocation of a run ends, what it cost on its own, which models it used, how long the agent ran, and what the subscription windows read — in one ledger that stays with the run.

> A cost is recorded once, per invocation, when it happens; no reader ever re-derives it from a provider stream.

## 4. Terminology

- **API-list cost** — what an invocation's tokens cost at Anthropic's API list prices; the common unit of cost, whatever the operator actually pays.
- **Invocation** — one `claude` process phax spawns in a run: a phase turn, a fix attempt, a handoff generation, a compliance review.
- **Cost ledger** — the persisted, per-invocation record of API-list cost, tokens per model, agent duration and rate-limit samples of a run.
- **Rate-limit sample** — one observation of a window: utilization (0–100 %), its reset instant, and the run's cumulative API-list cost at that moment.
- **Window** — a subscription limit: `five-hour` or `seven-day`.

## 5. Functional requirements

### 5.1 Ledger entry per invocation

WHEN a Claude invocation of a run ends THE system SHALL append to the run's cost ledger one entry carrying the invocation's phase, role, session id, tokens and API-list cost per model, total API-list cost and agent duration.

### 5.2 Rate-limit samples

WHEN an invocation's stream reports a subscription window THE system SHALL record in that invocation's entry a rate-limit sample with the window, its utilization, its reset instant and the run's cumulative API-list cost at that point of the stream.

### 5.3 Per-invocation cost, not cumulative

The system shall record each ledger entry's tokens and API-list cost as those of that invocation alone, also when the provider reports them cumulatively over a resumed session.

### 5.4 Invocation that ends without a result

IF an invocation ends without a result event (killed, rate-limited, crashed) THEN the system SHALL record its entry with the cost of the assistant messages its stream holds and mark it `partial`.

### 5.5 Ledger survives the run

The system shall keep a run's cost ledger with the run through archival and pruning, as it keeps the run's other records.

### 5.6 History backfill

WHEN the operator runs the backfill THE system SHALL write a cost ledger for every kept run that has none, derived from its kept streams under §5.3, and SHALL leave runs that already have one untouched.

### 5.7 Other providers

IF an invocation runs on a provider other than Claude Code THEN the system SHALL write no ledger entry for it.

## 6. Surface

Cost ledger, one per run folder (file name and layout indicative; per-entry fields normative). Versioned by shape with a `$schema` stamp like every persisted format; every field is required:

```json
{
  "$schema": "https://docs.phax.run/schemas/cost-ledger/next.json",
  "entries": [{
    "phase": "phase-02", "role": "handoff", "completeness": "complete",
    "provider": "claude-code", "sessionId": "2e1b99b9-5b4d-4141-8b94-90ebc61ff5fb",
    "models": { "claude-opus-5-5": { "inputTokens": 6, "outputTokens": 2378, "cacheReadTokens": 947932,
                                     "cacheWriteTokens": 5578, "costUsd": 0.28 } },
    "costUsd": 0.28, "agentMs": 41210,
    "rateLimitSamples": [{ "window": "five-hour", "utilization": 21, "resetsAt": "2026-10-15T18:10:00Z",
                           "runCostUsd": 8.98 }]
  }]
}
```

`role` is one of `phase`, `fix`, `handoff`, `compliance` (normative); `phase` is `null` for a run-level entry; `completeness` is `complete` or `partial` (normative).

Backfill command (indicative spelling; output wording indicative):

```
$ phax cost backfill
wrote 132 cost ledgers (1,326 invocations, $1,974.97 API-list)
$ phax cost backfill
nothing to backfill
```

## 7. Non-goals

- Estimating a plan's cost or judging it against the subscription windows — the `plan-estimate` spec.
- Displaying cost in `final-report.md`, the pull request body, `phax ls` or run records; the ledger makes it possible, a later spec decides where it shows.
- Recording `backend.complete()` calls (plan extraction, plan auditor), authoring sessions and the interactive code review.
- Codex and Mistral Vibe usage.
- Converting API-list cost to what the operator pays (subscription, usage credits).

## 8. Acceptance criteria

### Every invocation lands in the ledger

Given a completed run with one fix attempt per phase, when the run folder is read, then its cost ledger holds one entry per phase turn, fix attempt, handoff and compliance review, each with `role`, `sessionId`, `models`, `costUsd` and `agentMs`. (refs §5.1)

### Windows are sampled

Given an invocation whose stream reports the five-hour window at 21 % after $8.98 of run cost, when recorded, then its entry holds a sample `{ "window": "five-hour", "utilization": 21, "runCostUsd": 8.98 }` with the reset instant. (refs §5.2)

### Resumed invocations are not cumulative

Given a phase turn whose stream reports `costUSD` 8.71 and a resumed handoff whose stream reports cumulative `costUSD` 8.99 and per-invocation `usage`, when both are recorded, then the handoff entry's `costUsd` is 0.28 and the phase's entries sum to 8.99. (refs §5.3)

### Interrupted invocation is partial

Given a phase turn stopped by a usage limit before its result event, when recorded, then its entry is `partial` and its `costUsd` is the cost of the assistant messages its stream holds. (refs §5.4)

### The ledger follows the run

Given a run with a cost ledger, when the run is archived, then the archived run folder holds the same ledger. (refs §5.5)

### Backfill writes only what is missing

Given one archived run with kept streams and no ledger and one run with a ledger, when `phax cost backfill` runs, then exactly one ledger is written, its handoff entries carry per-invocation cost, and the existing ledger is byte-identical. (refs §5.6, §5.3)

### Other providers write nothing

Given a run whose phase-02 runs on `codex-cli`, when the run completes, then the ledger has no entry for phase-02. (refs §5.7)

## 9b. Arbitrated questions

### Q1 — Backfilling the kept runs

- A — ledger only, written from now on — abandons: the 132 runs already kept; the `plan-estimate` history stays empty for weeks.
- B — ledger at run time, plus a one-shot backfill from the kept streams — abandons: a backfill path to maintain until every kept run has a ledger.

Recommendation: B — the backfill is a bounded, deletable cost; A throws away the history the estimate is built on.

Decision: B — by operator (Rémy Loubradou), 2026-10-16
Why: as recommended. Revised: none.

### Q2 — Who reads the cumulative quirk

- A — correct it by the reported Claude Code version (resumed and ≥ 2.1.268 means cumulative) — abandons: robustness to a future version that changes the rule again silently.
- B — always take the per-invocation `usage` block and price it with catalog prices — abandons: Claude Code's own per-model split (sub-agents, Haiku side calls) and its exact pricing of cache writes.

Recommendation: A — the version is in every stream's `init` event, and the backfill's totals can be checked against B as a guard.

Decision: A — by operator (Rémy Loubradou), 2026-10-16
Why: as recommended. Revised: none.

## 10. Implementation-planning note

Settled: one ledger per run, one entry per Claude invocation, per-invocation cost and rate-limit samples recorded when the invocation ends; backfill from kept streams. The spike `spikes/plan-estimate/phax_estimate.py` (`per_invocation`, `scan_streams`) is the reference for the correction and the sampling. Left open: the ledger's file name and place (one run-level file or one per phase folder), the backfill command's final spelling. Constraints: the ledger is a new persisted format, versioned by shape, with every field required and no optional fallback; reading streams happens at the provider edge, the ledger enters the domain decoded through its schema; the run records' existing `usage` stays as it is.
