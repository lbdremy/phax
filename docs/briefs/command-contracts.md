Write the phax spec "Command contracts". phax's commands are written against a small command library, ported into phax, that puts each command under contracts — what it reads, what it answers, how it fails — and forces a machine answer: with `--json`, every command writes its output contract's JSON on stdout and its errors as JSON on stderr. Commander stays underneath, as the parser the runner uses; no command touches it again. This spec ports the library and moves every phax command onto it; among them, the three the brief `claude-code-mod` needs are set straight first.

**Why.** The operator, 2026-10-30. phax's commands are Commander commands, each printing what it chooses: 9 of the 65 commands of `phax.usage.kdl` have `--json`, and some of those print an unversioned document (`plans lint`, `plans overview`), and `artifact status` has none. An agent reading phax, or the Claude Code mod, cannot rely on a machine answer. The library the operator wrote outside this repository gives every command one contract, and will be published as a package; until then phax ports it, and replaces the port with the package when phax moves to Effect 4. The operator, its author, brings it under phax's Apache-2.0 licence; the package is published under MIT or Apache-2.0.

**The library, as of 2026-11-03 (TypeScript, Effect 4).** Two packages: the contract (what a command, a group and a program are, the two policies, the written-file record, the contracts catalogue, the usage spec, the message lines, and a conformance suite of cases by id that proves any runner), and its one runner, over Commander. The operator's revision of 2026-11-02/03 gave it everything below; its Rust twin carries the same contract and passes the same case ids.
- **A command** declares a `name`, a `summary`, an optional long `help` and `examples` (one command line each); its sources (`args`, positional and typed by position; `flags`; `stdin`, one JSON document; `env`), each an Effect Schema with its policy for what it does not declare (`reject` refuses the call, `strip` drops it); an `output` contract and its policy, required by the types when `run` succeeds with a value; an exit code for each tagged error its `run` may fail with (the type asks for every tag and no other) and, optionally, each error's fields as a schema for the catalogue; a `run`, the decoded input in, an Effect out; an optional pure `render`, the output and the terminal in, text out; optional `notes`, lines for the person on stderr beside the output, computed from the output; an optional `document` hook marking an answer that is a document (its bytes, its `$schema` format, the files written beside it); and `writesDocument`, which gives the runner the command's `--out`.
- **A group** (`defineGroup`) holds commands under one word, `<program> <group> <command>`; each command keeps its own contract and codes; the group called alone writes its help on stderr and is refused. Groups hold commands, not groups: one level.
- **A program** names its commands and groups, its version, and its runner's two codes: `refused` (an unknown command, an undeclared argument or option, a source or document that does not decode, a stdin read wanted while stdin is a terminal) and `defect` (what no command declared: a death, an output that does not encode). A command may answer with `refused`, never with `defect`; a program where they collide, or where a command declares an option `json` (or `out` beside `writesDocument`), runs nothing, names the command and exits with `defect`.
- **The process is data** (`Io`: argv, stdin read only when declared and never when `stdinIsTerminal`, `readFile`, `writeFile`, env, the terminal, `out`, `err`), so a runner is proved without one.
- **The runner** decodes each declared source with its contract and its policy, runs the command, encodes the value with the output contract, and writes `render`'s text, or the encoded form when the command has no render. Without `--json`, a declared error is written on stderr as `Tag {fields}` (Effect's formatter) with its code, a refusal as `error: …` text, a defect as `defect: …`. `--help` and `--version` stay text. It builds a fresh Commander tree inside each call and hands no Commander object out. The program's hidden `--usage-spec` writes its usage spec in KDL from the definitions: each command and group, each positional and option by its name with its help from the schema's annotations, its default and a literal union's choices, the long help, the examples, and `--json`.

**Settled by the operator (do not reopen)**, on 2026-10-30, amended on 2026-11-02 where the library's own spec settled the document's flag, the layout of `--json`, the error lines and `--json-schema`, and on 2026-11-03 for the library's revision:
1. **Ported, not depended on.** The contract and its Commander runner are ported to Effect 3 into phax's own source (their place and names are the spec's), with the conformance suite, and changed in phax only where Effect 3 asks or where phax needs what the library lacks (below). Each such gain is written as the library would carry it, so that it can go upstream and the published package can replace the port. phax's own commands import the port, never Commander. When phax moves to Effect 4, the published package replaces the port; that is a later spec.
2. **A machine answer, forced.** These rules are the library's; the spec states them as such and phax takes them as they are:
   - a command that answers a value declares its output contract; `render` is optional, the human view drawn from it; a command with no render prints its output's encoded form, with or without `--json`;
   - `--json` is the runner's, reserved on every command, grouped ones included, and listed in each command's help and in the usage spec. It writes the output's encoded form, never `render`'s text, indented by two spaces with one trailing newline, `$schema` first when the output has one. An explicit flag, not a switch on the terminal ([clig.dev](https://clig.dev/));
   - under `--json`, stderr holds message lines only, one compact JSON object per line, tagged by `kind`: `note` (`text`), `written` (`path`, `format`, `digest`), `error` (`error`, the tag; `exit`; `fields`; `written`, the files written before the failure), `refused` (`source`: `args`, `flags`, `env`, `stdin` or `command`; `path`, the field that failed; `expected`; `text`, the refusal's text form; `exit`) and `defect` (`text`, `exit`). No line carries a `$schema`: they are a stream beside the output, read by an agent that runs the command and acts on the error, never by a pipe, which carries stdout only; their shapes are published once, under `messages` in the contracts catalogue. Exit codes unchanged. Without `--json`, stderr is text, as above;
   - a document carries `$schema` first, the output's as the input's; the output contracts are where phax's published JSON Schemas come from (`packages/schemas`). A command whose answer is a document marks it with the `document` hook: the runner writes its bytes as they are, in both modes, and under `--json` writes one `written` line for each file listed beside it;
   - **the contracts are printed by the runner's `--json-schema`**, reserved like `--json`: on the program, `phax --json-schema` prints the contracts catalogue (`program`, `version`, `exits` with `refused` and `defect`, `commands`, `messages`); on a command, `phax plans lint --json-schema` prints that command's entry alone, equal to its entry in the catalogue: its full name as a list of words, its `input`, its `stdin` (`flag`, `required`, `schema`, or null), its `output` and its `errors` (`tag`, `exit`, `fields`), all JSON Schema 2020-12. It runs no command, as the AWS CLI's per-command `--generate-cli-skeleton input|output` does. The word is schema, the one agents know from MCP's `inputSchema` and `outputSchema`. `phax artifact schema spec|plan|verdicts` keeps printing the documents' formats, as `terraform providers schema -json` describes its resources;
   - **a document is read from the source named `stdin`**, which keeps that name and its contract. With no flag bound to it, stdin is always read, and refused at once when it is a terminal, never waited on. A command may bind a flag to its stdin (`stdin: reject(Contract, { flag, required })`), named by the command for what the document is, its value optional: without the flag, stdin is not read; the flag alone or with `-` reads stdin, refused at once when it is a terminal; the flag with a path attached (`--flag=<path>`) reads that file instead, stdin never opened. A document the command requires behind a flag is refused at once without the flag, naming it. A file that cannot be read, a document that is not JSON or does not decode is refused before `run`, naming the path or stdin and the field that failed. Arguments and options say what the command acts on; the document is its content;
   - **the files a command writes are part of its output**: each as a written-file record, `path` (from the repository's root), `format` (the document's `$schema`, or null for a file that is no document) and `digest` (`sha256:` and 64 lowercase hex digits), never its content again; a command that writes one document declares `writesDocument` and so takes the runner's `--out <path|->`: with a path the document is written there and the record is the answer, with `-` or without `--out` the document itself is the answer; a command that fails part way lists what it already wrote in its error's `written`.
3. **Every command moves.** All of phax's commands are registered through the runner in this spec, so `--json` means the same on every command once it ships; the plan orders them by family. The three the brief `claude-code-mod` reads come first:
   - `phax artifact status` gains `--json`: a versioned `artifact-status` document — kind, status, legal transitions, approval and approver, edited since approval, authoring mode and sidecar sync, the questions open and arbitrated;
   - `phax plans overview --json` becomes a versioned `plan-overview` document, `$schema` first; `phax plans lint --json` too;
   - `phax ls --json` (the run list; the brief `claude-code-mod` calls it `runs list`) keeps its `run-list` document, adding each run's pull request when phax opened one.
   Each keeps its text output for a person, now its `render`.
4. **The contracts phax publishes do not change** except where a document gains `$schema` or a field above: a document that is versioned today stays byte for byte. `phax --usage` stays the contract of the command line: what a migrated command declares there does not change.
5. **The codes phax documents stay.** The program's `refused` and `defect` are phax's own (the spec names them from `phax --usage`), and each command keeps the codes its help documents.
6. **A command that prints a `--json` today** keeps its document: the runner's `--json` writes that document as the command's output contract, byte for byte where it is versioned.
7. **`phax.usage.kdl` is written from the contracts.** Today `scripts/generate-usage-spec.ts` walks the live Commander tree, with `src/cli/cliDocs.ts` for the long help and examples and `src/cli/cliCompleters.ts` for completion. The ported runner hands no Commander tree out: there is nothing left to walk. The library's usage spec, written from the program's definitions, takes its place, and the script calls it and writes the file. What `cliDocs` holds moves into each command's definition (`help`, `examples`), and each argument's and option's help into its schema's annotations. The parity gate becomes: the file is the generator's output; what a command declares in it does not change (point 4).

**What the library lacks for phax.** Facts read from the library on 2026-11-03. Each is a gain the port makes (point 1) or a §9 question when two answers are viable:
- **Nested groups.** `phax artifact new spec|plan` and `phax agent setup providers|mistral-vibe` are three words deep; the library's groups hold commands only.
- **Completion.** `phax.usage.kdl` declares `complete` nodes (run names from `phax ls --complete`), written from `src/cli/cliCompleters.ts`; the library's usage spec writes none.
- **An answer with a non-zero code.** `phax plans lint` prints its report and exits 1 when a finding is an error. The TypeScript library maps only failures to codes. Its Rust twin has a verdict: a command declares the codes its output may answer with, and the output is printed all the same with that code; a code not declared is a defect.
- **A text document.** `phax artifact new spec|plan --brief <file|->` reads a Markdown brief; the library's `stdin` is one JSON document.
- **Progress while a command runs.** `phax run`, `resume`, `artifact decide` and the authoring sessions write progress and record lines on stderr as they go; the library's `notes` come from the output once `run` is done, and under `--json` nothing but message lines may reach stderr.
- **An error's text for a person.** Without `--json`, the library writes a declared error as `Tag {fields}`; phax's errors are sentences naming their remedy, which its help, docs and tests quote.
- **`--usage` and `--usage-spec`.** phax answers `phax --usage` with its usage spec; the library's runner reserves the hidden `--usage-spec` for the same thing.
- **The program's codes.** phax documents no code for an unknown option or an unexpected crash; today both exit 1, as the phase guard does. The library's own tests use `refused: 64` and `defect: 99`.

**Out of scope:**
- phax's move to Effect 4 and the replacement of the port by the published package;
- the Claude Code mod itself;
- a flag that only validates the input and stops — an idea, wanted by agents before a command that writes;
- `--help` and `--version` in JSON: they stay text, as in the library.

**Surfaces.** A surface's `summary`, `before` and `after` are read by users in the release notes: a capitalized sentence and short real examples, with no implementation notes. Name `$schema` URLs at 0.34.0, the release this ships in. Fixtures and names in examples are made up.
