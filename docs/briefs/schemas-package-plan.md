1. **Read the phase record** (write this one): the package skeleton with its single entry and the `Parsed` API; the phase record's current shape and its frozen legacy shapes v1 and v2; `toLatestPhaseRecord`; the newer-release failure; `parseDocument` recognising the phase record. A requirement of the spec that belongs to a later plan is out of this plan's scope; list in the preamble which requirements and acceptance criteria this plan covers.

What the plan must respect beyond the phax-planning skill:
- **Order across the five plans** (for reference; this plan is only the first). Land the reading-history machinery before the format changes it guards: first the package skeleton and the parse API for the current shapes; then the frozen historical decoders of the legacy shapes (phase record v1 and v2; the authoring record v1 accepting both legacy shapes, with and without `sourceSha`), `toLatest` per format, and the newer-release failure; then `parseDocument` (identification by `$schema` alone); then the committed JSON Schema snapshots keyed by format and shape, and the snapshot gate; then the history-corpus script and the committed corpus, parsed in the release gate; only then `$schema` written as the first key of every persisted format with `version` dropped, so the snapshot gate records that shape change at the release; last the release workflow, `release.sh` and the README table.
- **Identification (revised 2026-09-28).** A document is identified by its `$schema` URL (`https://docs.phax.run/schemas/<format id>/<release>.json`), never by its file name or location; there is no per-format `version` in new documents and no `producedBy`. Read the spec's terminology (Format id, Schema URL, Shape, Legacy document) and requirements `schema-url`, `identify-alone`, `snapshot-gate`.
- **Revised again 2026-09-28 (spec §9 q-no-experimental, q-release-name, q-own-legacy).** One package entry for every format: no `/experimental` entry, no stability keyword, one `parseDocument`. `$schema` names the root `package.json` version: no release-version constant. An unreleased shape is `snapshots/<format id>/next.schema.json`; `release.sh` renames every `next` snapshot to the version it cuts. phax reads a file it wrote in an older shape (registry, run and phase status) through the package's historical decoders and `toLatest` — no one-step lift inside phax — and refuses naming the file when a fact it needs is unknown.
- **Validate on one example first** (steme working principle 6): the first phase that parses history does it for the phase record alone (`toLatest`, the newer-release failure) and stops there, before the pattern is repeated for every format. The corpus script comes with plan 3: plan 1 tests against a few real phase records (v1 and v2) copied by hand from `~/.phax/records/phax` into test fixtures.
- **The corpus source.** phax's records live in the separate `phax-records` repository (records destination in `phax.json`); a local clone sits under `~/.phax/records/phax`. Each commit of `phax/records/v1` carries its own tree, so the script walks every commit, not the branch tip. The spec leaves open how the script finds that history (§10 open): choose a path argument, and say so in the plan's technical arbitrations.
- **Coordination.** artifact-decide, headless-review and oracle-phases (all Approved) change formats this package exports; their plans come after this one and record their changes as new shapes through the snapshot gate. This plan does not implement any of their changes.
- Gate: the plan must pass `phax plans lint`; every phase's commands must be allowed by `phax.json`.
