**Scope.** The whole spec: every §5 requirement and acceptance criterion, and every §6 surface. Nobody uses Vibe through phax today, so there is no migration.

**Facts every phase can rely on** (live probes against Vibe 3.0.3, 2026-10-27; reproduce them as unit fixtures):
- A stream entry, one per line: `{"id":…,"sessionId":"b8e0e3a1-9ad8-2100-46e7-4a199256f640","turnId":…,"createdAt":1793116136395,"type":"message","role":"assistant","content":[{"type":"text","text":"PONG"}],"source":"harness","outcome":{"type":"committed"},…}`. Tool calls are `type: "effect"` entries (`detail.toolName` such as `file_system.bash`, `state.status`, `state.decision`); approvals are `type: "callback"` entries.
- `export.json`: `{"outcome":"finished","stop_reason":null,"error":null,"session_id":"b8e0…","usage":{"input_tokens":10987,"output_tokens":3,"cached_input_tokens":3200,"total_tokens":10990},"cost_usd":0.016503,"steps":1,"schema_version":1,"vibe_version":"3.0.3","journal_dir":"session","started_at":…,"ended_at":…,"limits":{…},"exit_code":0,"config":{…}}`. Usage and cost count that run only. The output directory also receives a copy of the session journal under `session/`.
- `vibe --version` prints `vibe 3.0.3`.
- Secure controls, all per invocation through the environment, with `--agent accept-edits`: `VIBE_OUTSIDE_WORKDIR=deny`, `VIBE_TOOLS='{"bash":{"permission":"ask","allowlist":[…]}}'` (JSON). Headless, a call no rule allows is refused (`tool_denied`, or "denied by approval policy"), the model reads a tool error, and the run goes on.
- `--enabled-tools read_file --enabled-tools grep` refuses `write_file` and `bash`. `--disabled-tools '*'` refuses every tool call, and the model still answers.
- Vibe merges config layers deeply (environment over user TOML, a list replacing a list, unset keys kept from below), so a user's `bypass_tool_permissions = true` or a file tool's `allowlist` survives unless phax sets those keys itself.

**Settled technical arbitrations (record each in Technical arbitrations with its loss; do not reopen):**

- **Where a turn's Vibe export lives.** Each headless Vibe turn gets `--output-dir` set to its transcript path with `.jsonl` replaced by `.vibe-export` (`output.jsonl` → `output.vibe-export/`, `fix-01.jsonl` → `fix-01.vibe-export/`). - **Usage counts every turn**, one export per transcript the caller lists, never deduplicated by session id. A missing or unreadable export makes the whole usage unavailable, as for the other providers. Loss: none; the old dedupe existed only because `meta.json` held whole-session totals.
- **A stop's Vibe transcript.** `TranscriptRequest` gains a required `phaseFolder`. The Vibe capture lists the `*.jsonl` files directly in it, keeps those whose first decodable entry carries the session id, orders them by that entry's `createdAt`, concatenates their bytes, and returns `missing`/`not-found` when none matches. Claude Code and Codex ignore the field. Loss: a session the person ran in Vibe's TUI has no transcript (the spec's decision).
- **Missing reads are named (spec §5.4).** A turn with no `export.json` in its output directory, or no assistant message entry with a text block, fails as an `AgentInvocationError` naming what is missing and the path read.
- **The version floor.** The adapter runs `vibe --version` once per process (memoized per executable) before its first Vibe session, and refuses below 3.0.3, or on an unparseable answer naming what it printed, with an `AgentInvocationError`. Loss: one short process per phax process that uses Vibe.
- **The secure environment.** `VIBE_OUTSIDE_WORKDIR=deny`, `VIBE_BYPASS_TOOL_PERMISSIONS=false`, and `VIBE_TOOLS` holding `bash` with `permission: "ask"` and `allowlist` equal to the session's agent commands, plus `read_file`, `write_file`, `edit` and `grep` each with `allowlist: []`. The argv carries `--agent accept-edits`, `--workdir`, and `--add-dir` for each writable root beyond the worktree. Loss: a user's own allowlist entries never reach secure phax sessions.
- **Narrowing.** A read-only session runs `--agent accept-edits --enabled-tools read_file --enabled-tools grep`; with agent commands it adds `--enabled-tools bash` and the secure `VIBE_TOOLS`, plus the two other secure variables. A sealed completion runs `--agent accept-edits --disabled-tools '*'` with the same two variables, `--workdir` the completion's cwd, no `--add-dir`. Secure mode does not deny `web_fetch`/`web_search`, matching Claude Code's secure flags. Loss: the model still sees tool names; its calls are refused.
- **Remove the writing closing turn.** Once every provider's stop turns are read-only, `turnsCanWrite` and the restore of an interrupted writing closing turn's edits (`LeftoverSettlement.restoredClosingTurn`, its kept versions, its stop-output line) have no provider left: remove them rather than leave a branch no provider takes. Loss: an interactive-session document an older phax left with a Vibe writing closing turn in progress is settled as a read-only turn; its edits stay in the worktree and the next close's comparison reports them.

Every format embedding it moves to a `next` snapshot at 0.30.0, with its current shape frozen under `src/schemas/history/<format>/<stamp>.ts` and stamp routing, as commit 351d3267 did for decision-record-manifest 0.25.0.
