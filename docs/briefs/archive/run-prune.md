Write the phax spec `run-prune`: a `phax prune` command that deletes archived runs for real, so their names become free again and their disk space is returned. It closes the run lifecycle (created → … → archived → gone).

Why (NEXT_STEPS.md, §"Road to 1.0.0" "`phax prune`" and §"Spec candidates" "`phax prune` — delete archived runs", raised 2026-09-08): run names must never collide, so the registry keeps archived runs as name-holders, and the only way to free a name is to delete the archived run, not to weaken uniqueness. `archive` moves and keeps; `prune` removes. On the author's machine today: 123 runs in the registry, all archived; `~/.phax/archive` holds 86 GB; 22 runs carry a `-2`-style suffix; the phax repository alone has 375 local `phax/<name>--phase-NN` branches left by past runs.

What an archived run is made of (read `src/app/archive.ts`, `phax --usage` cmd archive, and the registry entry shape in `src/schemas/`): the folder `~/.phax/archive/<namespace>.<short-name>/` (its `runs/` copy of the run directory and its moved `worktrees/`), the registry entry (`state: archived`, `archivePath`), the git worktree metadata in the project repository, the run's local branches in that repository (`phax/<name>` and the per-phase `phax/<name>--phase-NN`), possibly their remote branches and pull request, and its records on the `phax/records/v1` branch.

What the spec must cover:
- What `prune` deletes and what it never touches. Proposed defaults, to confirm or change in §9: it deletes the archive folder, the registry entry and the worktree metadata; it never touches the records branch (records are the run's lasting history and are keyed by run id, not by name), remote branches or pull requests; local branches are an open question (deleting a branch whose commits are not merged anywhere loses work).
- Which runs it accepts: only `archived` runs (never a live, running or locked one); selection by short name, and whether a bulk form exists (for instance `--all`, or an age filter). Namespaces: the registry spans several repositories (phax, steme-lab, louloupapers…); say whether `prune` works on the current repository's namespace only, as `archive` does, or across namespaces, and how it reaches another repository's worktree metadata and branches.
- Safety: whether it previews by default (`--dry-run` or a listing before deleting) and requires confirmation (`--yes` when there is no TTY, like other destructive commands); what it prints (runs, bytes freed, branches kept or deleted); partial failure (a folder already gone, a repository moved or missing) — idempotent and reported, never a stack trace.
- The name afterwards: after `prune`, `ensureUniqueShortName` no longer sees the name, so the next run of the same plan gets the bare slug. Say what happens when the old `phax/<name>` branch still exists locally or on the remote at that point (collision on branch creation?), and how `run` handles it.
- The CLI contract: command name, arguments, flags, exit codes, `--json` output if `runs list` has one; the `phax.usage.kdl` entry, the CLI docs. Acceptance criteria for each behaviour.
- Out of scope: the preflight-before-naming fix (a separate spec), deleting records, deleting remote branches or pull requests, automatic pruning or retention policies.

Ground to read first: NEXT_STEPS.md (entries above), `src/app/archive.ts` and its tests, the registry (`src/infra` / `src/app` registry reader and writer, its schema in `src/schemas/`), `ensureUniqueShortName` and `src/cli/commands/run.ts`, `phax --usage` (cmd archive, cmd runs list, the exit-code families), and the persisted-format promise (the registry is a public format of `@lbdremy/phax-schemas`; prune removes entries, it must not change the shape).

Constraints: additive to the CLI (a new command; no existing command changes behaviour); no persisted-format change. §9: genuine choices only, each with options, what each abandons, and a recommended default — at least the local-branch question, bulk selection, cross-namespace reach, and preview/confirmation.
