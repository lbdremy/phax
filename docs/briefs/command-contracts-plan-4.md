**Lessons from plans 1 to 3 (do not repeat):**
- A command's text is its streams and its sentences. Lines printed on stdout before a failure stay on stdout (the `{ out, err }` text form); Commander's own sentences stay (`error: option '--x <value>' argument missing`); a refusal's remedy names the flags that lift it.
- An answer is what the call did: written-file records list the files written on this call, read back, never a write set or a plan; every field is filled on every path where its fact exists (plan 3 set `deletedRecord` on a reopen only).
- An acceptance test copies the spec's normative example key for key, types included (plan 3 asserted `"0"` where §6 writes `0`), fails on its own assertions, and carries its expected-failure marker on its own `it`; the passing phase removes only that marker.
- A document read on stdin or from a file is refused before `run` when its `$schema` names another release, not answered later with another code.
- When code moves out of a directory a guard scans, the guard's scope moves with it; an allowlist entry is moved with its reason, never dropped.
- Today's exit codes stay, success codes included: no new verdict a command did not have.
- A test fixture that commits sets its own git identity; no test holds a fact the release cut changes (a snapshot named `next`, the version in `package.json`).
- `docs/upgrading.md` names every change a person or a script can observe, help layout, group output and retired words included; it never says "unchanged" for a command whose streams, codes or help moved.
