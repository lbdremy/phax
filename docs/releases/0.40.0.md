# phax 0.40.0

Changes since 0.39.0: [v0.39.0...v0.40.0](https://github.com/lbdremy/phax/compare/v0.39.0...v0.40.0).

## Highlights

- **Code repository: a plan's process in one repository, its code in another** — A plan's ground is the code it reads, in whichever repository that code lives.
- **Finding ids and fates** — No finding is dropped: phax names it, the operator or a machine settles it through a phax command, and Git remembers how.

## Upgrading

- **The pull request description's code review findings list is replaced by a Review findings section** of every finding by fate: open and deferred named, fixed and dismissed counted.
- **With `publish.auto` on, `phax finding fix`, `dismiss` and `defer` now push and comment on the run's existing pull request**, `fix` only while GitHub reports it open, and their `--json` answers gain `pullRequest`. Exit 1 now also covers a pull request not updated.
- **`phax finding post` is new.** It posts the comments of settled findings without recording a fate again.
- **`code-review` and `compliance-review` move to 0.40.0 shapes whose findings carry an `id`.** An `@lbdremy/phax-schemas` before 0.40.0 refuses them, so upgrade the package. The package reads the 0.32.0 shapes with each id `Unknown`.
- **The review sessions answer new formats**, `code-review-answer` and `compliance-review-answer`. phax gives each finding its id and keeps the answer as `code-review.json` or `compliance-review.json`.
- **`phax finding list --json` prints the new `finding-list` document.** See [Review findings](https://github.com/lbdremy/phax/blob/v0.40.0/docs/findings.md).
- **`phax finding fix`, `dismiss` and `defer` record fates** as `finding-fate-record-manifest` records on `phax/records/v1`, keyed `<runId>/finding/<id>/<NN>`, which `phax records list` does not show. An `@lbdremy/phax-schemas` before 0.40.0 cannot read them, and `parseRecordManifest` refuses them: read them with `parseFindingFateRecordManifest`.
- **`finding-list`'s `history` now holds fate records.**
- **Fixing commits carry `Finding:` trailers** beside `Short-Name`.
- **`plan-approval-record` moves to a new shape with a required `code` key**: `null` without a code link, `{ root, baseline }` with one. An `@lbdremy/phax-schemas` before 0.40.0 cannot read new plan approval records, so upgrade the package.
- **Records written earlier are read as `code: null` and never rewritten.**
- **Declaring a code link makes plans approved before it `missing-record`**, so re-approve them. See [Process and code in two repositories](https://github.com/lbdremy/phax/blob/v0.40.0/docs/code-repository.md).
- No step is needed in a repository that declares no code link.

## What's new

### Code repository: a plan's process in one repository, its code in another

> A plan's ground is the code it reads, in whichever repository that code lives.

- A process repository names the directory where its code repository is checked out, and phax judges its plans against that code. `phax.json code (process repository, project layer only)`

  Now:

  ```text
  {
    "gateProfiles": { "default": [ … ] },
    "code": { "root": "code" }
  }

  # .gitignore of the process repository
  /code/
  ```

  ```text
  {
    "gateProfiles": { "default": [ … ] }
  }
  ```

  </details>

### Finding ids and fates

> No finding is dropped: phax names it, the operator or a machine settles it through a phax command, and Git remembers how.

- Each code-review finding now carries a stable `id` such as `F3` that commits, records and people can point at. `code-review.json`

  Now:

  ```text
  {
    "$schema": "https://docs.phax.run/schemas/code-review/0.33.0.json",
    "findings": [
      { "id": "F1", "severity": "bug", "file": "src/app/gate.ts", "line": 42,
        "message": "retry loses the gate's exit code",
        "lens": "core", "escape": "omission", "criterion": "AC-retry",
        "suggestion": "carry the exit code through the retry" }
    ]
  }
  ```

  <details>
  <summary>Before</summary>

  ```text
  {
    "$schema": "https://docs.phax.run/schemas/code-review/0.32.0.json",
    "findings": [
      { "severity": "bug", "file": "src/app/gate.ts", "line": 42,
        "message": "retry loses the gate's exit code",
        "lens": "core", "escape": "omission", "criterion": "AC-retry",
        "suggestion": "carry the exit code through the retry" }

  ```

  </details>

- An operator can mark one or more findings dismissed with a required reason, stamped with their name and the time. `phax finding dismiss`

  Now:

  ```text
  $ phax finding dismiss gate-retry F3 --why "the second check guards --resume"
  ✓ recorded F3 dismissed on phax/records/v1 (by Rémy Loubradou)

  $ phax finding dismiss gate-retry F3 --by machine:review-bot --why "…"
  ✗ dismiss refused: only an operator dismisses a finding
  ```

- An operator can hand a finding to later work by naming the brief, spec or NEXT_STEPS.md that takes it over. `phax finding defer`

  Now:

  ```text
  $ phax finding defer gate-retry F5 --to docs/briefs/gate-retry-docs.md --why "docs pass after the gate rework"
  ✓ recorded F5 deferred → docs/briefs/gate-retry-docs.md on phax/records/v1

  $ phax finding defer gate-retry F5 --to docs/briefs/nope.md --why "…"
  ✗ defer refused: docs/briefs/nope.md is not a tracked file
  ```
